**2026-08-23.** Branch `feat/npx-public-install`, PR #75, forked from `main` at `d8ee85f`.
This file is a record of what was done and what was measured. It is amend-only
(`tools/amendguard/ledger.json` → `docs/eval-data/*.md`).

No `git tag` (tags remain at 22). No `npm publish`, `npm adduser` or `twine`. `runtime-py/`
was not modified: **0 files** across every unit. The live memory store
(`.bantamkit/memory`, 65 facts / 13,472 bytes) was copied to scratch by every probe that
touched it and is unchanged.

The procedures this job produced are documented separately, and those are the files to read
if you are doing the work rather than auditing it: [porting.md](../porting.md),

## The ruling this job implements

> "เป้าหมายในการ publish คือทีมฉันใช้ node npx ก็ควรใช้แค่ npx แล้วรัน node แทน pipe/uv"

Pure Node, run by `npx`. No Python at runtime, no `uv`, no `pipx`, no bootstrap that fetches
an interpreter.

## Method

Eleven shift-work units against `.shiftwork/job38-npx-public-install/checkpoint.json`. Each
unit was clocked in, handed its brief verbatim, and clocked out with accounting. Two rules
shaped the result more than any technical decision:

1. **Every unit had to refute something it was told.** Eighteen orchestrator claims were
   killed that way, and they are tabulated at the bottom because that table is the
   most useful part of this file.
2. **Non-vacuity is measured, not asserted.** A behaviour lands with a node demonstrated RED
   first, and vacuity is checked by mutation.

## The prep probe refuted the plan before it was written

Per `feedback-prep-probe-before-planning`, a probe ran before any unit was planned. It
refuted the port-surface figure by roughly 3×: the behavioural closure measured with
`sys.settrace` is **545 executable statements across 7 modules**, not the ~1,846 from recall
nor the ~3,700 of the follow-up guess. The AST import closure — 8,396 lines, 20 modules —
counts modules that arrive through `__init__` re-exports and never execute. `client.py` and
`memory/divergence.py` execute **zero** call-time lines on the MCP path.

It also surfaced the three real risks, none of which were on the original plan: the PyYAML
emitter, the index budget, and the fact that production runs layered.

## The review unit refuted the headline number

Six units had been reporting "19 ruled-different, 0 failures". Three of those nineteen
**could not have failed**:

- one compared a JS `str.replace` against itself — differs iff the text has a newline, i.e.
  always;
- two compared `'(valid)'` against `'null'` while **both** runtimes said valid, because their
  instances were arrays and `minimum` / `pattern` never fired.

The harness's teeth were then demonstrated rather than claimed: making a live ruling match
produced `STALE RULING: the case no longer differs` and exit 1. All three were rewritten and
one produced a real port fix (`\d` → `\p{Nd}` with the `u` flag).

This also produced the discipline now in [conformance.md](../conformance.md): a ruling fails
only when the two sides **match**, so it pins the *wording* and can never prove that both
sides still refuse. Where the refusal is the property, it gets its own non-ruled case.

## Two severity-1 defects, found by review and fixed by a dedicated unit

**S1 — one hand-edited fact bricked the whole Node store while Python kept working.**

```
store: good-one.md (healthy) + bad-one.md (description: 2026)

PYTHON:  recall -> ['good-one']   index -> 77 bytes
NODE:    recall RAISED            index RAISED
```

13 of 17 scalar shapes did this. The source comment justifying the refusal claimed Python
"reaches the model as a `TypeError` several frames away" — **CPython raises on zero of
seventeen.** A wrong belief, load-bearing.

The fix is the `PyScalar` design in [porting.md](../porting.md#pyscalar-what-a-fact-field-holds),
and it required porting CPython's `listsort` for the recall tie-break: 50,000 seeded lists,
CPython's `sorted` raises on 45,629, **50,000/50,000 agree**.

Over the 26-shape probe, CPython raises on 4 and *answers* on 22 — so the brief's property
statement ("a malformed fact is refused when it is the fact you asked for, and is otherwise
invisible") was wrong, and the port implements Python's actual behaviour instead.

**S2 — `validate_json` answered where Python refuses.** `{"valid": true}` on four schemas
`jsonschema` rejects, and on `{"type": 3}` it invented the sentence *"is not of type 3"* about
a schema that is not a schema. `checkSchema` now runs first: **53 malformed schemas, 53/53
refuse on both sides.**

Mutation sweep for the fix unit: **29 mutations, 29 red, 0 survivors** — two survived the
first pass and both were fixed.

## CI found three things eight units of local green had hidden

The CI unit ran last by design, so it would test final code. That ordering cost something:

1. **A test read the live, gitignored `.shiftwork/…/checkpoint.json`.** It passed only because
   the orchestrator was mid-job, and it moves as `plan.cursor` advances. Three conformance
   suites did the same and died at import, so `store` / `validate` / `wire` — **3,369 cases**
   — had never run on a runner while every unit quoted them.
2. **The server tests bound a store outside their scratch bed.** `session()` defaulted `cwd`
   to the repo root with an inherited `HOME`; with no `--store` that is `Memory.layered`,
   which walks up and **creates**, and `_stamp` rewrites on every recall hit. An empty
   `~/.bantamkit/memory` is the only reason the operator's own store was not touched.
3. **`core.autocrlf` on the Windows image** made the same commit produce a different
   `assets_digest`. Fixed with `.gitattributes * -text`.

Non-vacuity was demonstrated on the real runner, not argued: one deliberate byte in
`formatFact` moved every cell on both gates.

| cell | npm test | conformance |
|---|---|---|
| ubuntu 18 / 22 | 201 → 197 | 0 → 86 failures |
| windows 18 / 22 | 196 → 192 | 132 → 197 failures |

RED run `32646042930`; GREEN run `32646521489` after a byte-clean revert.

`engines.node >= 18` is **backed**, and was refuted before CI even ran: `assets.test.mjs` was
5-pass/5-fail on 18.20.8 because the *fixture* planted `dist/` in a tree with no
`package.json` and leaned on version-gated module-syntax detection. The shipped package always
had `"type": "module"`. Both Node versions produce identical numbers on each OS.

## The two Windows-only measurements

Both were labelled `NOT MEASURED HERE` until a runner could construct them, and neither was
settled by the one-liner the brief proposed — the store suite already carries byte counts, so
the Windows cells produced the reading by running at all.

```
index.md      42 bytes on disk / 41 counted     1 line
fact file    134 / 124                         10 lines
checkpoint  2609 / 2516                        93 lines
```

Exactly one byte per line, every time. So `on-disk = counted + lines` is a measured rule and
13537-vs-13472 is arithmetic on it, not a second measurement. The CRLF ruling is confirmed and
**wider than it claimed**: `index.md` and checkpoints translate too, so on Windows the two
runtimes do not write byte-identical stores at all.

## Concurrency

12 pipelined saves all landed in order; a recall behind a save **sees** the save in Node and
does **not** in Python; two processes over 8 trials × 15 saves gave 0 disagreements.

The one hazard — concurrent same-unit `clock_out` losing a history entry — is **10/10 on Node
and 10/10 on CPython.** Reproduced, not introduced, and deliberately not fixed on one side.
It was nearly filed as a port defect before the Python side was run.

## Registered against `runtime-py`, not fixed

4. `_pinned_store`'s docstring states a false reason.
5. A `pattern` regex divergence.
