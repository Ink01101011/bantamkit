## Deviations from the plan (property kept)

1. **Git runs only once the touch log has something to say.** The plan's `_touch_summary` runs `ls_files` before
   it knows there is a previous session; this one reads the log first and returns `""` before any subprocess when
   there is no previous session (startup) or no row at all. Same line; the silent path costs no git
   (latency below).
2. **`uncommitted_count` parses the `-z` status instead of `e[2] == " "` alone**: after a rename/copy entry
   (`R`/`C` in `XY`) the next field, the source path, is skipped. The plan's filter counts a source path whose third
   character is a space (`ab c.txt`). Case `uncommitted #01`; mutation M6 below.
3. **`now` is `utc_now()` / `utcNow()`, not `_stamp()`.** The usage ledger's parser (the plan says to use it) takes
   `YYYY-MM-DDTHH:MM:SSZ` exactly; `_stamp()` has milliseconds and would raise.
4. **Rules the plan left open, written in both module headers:** rows considered are touch rows (`read`/`edit`/
   `write`) with a ledger-stamp `ts` and string `session`/`path`; "most recently touched" is `seq` descending, ties
   (or a missing `seq`) by later log position; a tie on the latest `ts` goes to the smaller session id by code point
   (`cmpCodepoint` on Node — conformance pins U+FFFF over U+1F600, which UTF-16 order reverses); age is floored and
   never negative; `"1 file"` singular.
