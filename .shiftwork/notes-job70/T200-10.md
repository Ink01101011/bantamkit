## What changed (both runtimes)

1. **B2: no git on PATH records nothing.** `touch.repo.git_on_path` / `gitOnPath`: a stat walk
   over each non-empty `PATH` entry, never a subprocess; POSIX `<dir>/git` a regular file with
   `X_OK` (a symlink to one counts), Windows `<dir>/git<ext>` per `PATHEXT` (default
   `GIT_PATHEXT_DEFAULT = ".COM;.EXE;.BAT;.CMD"`); cached per process keyed by PATH/PATHEXT.
   `_record_touch` / `recordTouch` return before the counter when it answers false.
2. **No dead work.** `_touch_context` / `touchContext` return `None`/`null` before any read
   when `retrieval.W_CONTEXT == 0.0` and `via_enabled()` is false. Reply bytes unchanged; the
   UserPromptSubmit record's `context` count is absent in that state.
3. **Bounded log.** `TOUCH_LOG_CAP_BYTES = 1_000_000` (equal to `ROTATE_BYTES`) in both
   `touch/log.*`. An append (touch or use) whose `seg.size` passes the cap calls `bound()`:
   `fold_cutoff(bytes)` = `<ts>~` for the first object line with a non-empty string `ts` whose
   end passes the byte midpoint `len // 2`, then `LogSegment.fold(cutoff, touch_reducer)` (under
   the O_EXCL lock). `<=` the midpoint second, so a one-second log folds. Never raises.
