## Deviations from the plan (property kept in each)

   shows only the `set version 1` op and a comment). So nothing was renamed; a NEW per-side literal
   `LITERAL: #200 refs — docs carry their path references, and the head is version 5` pins both `refs` and `version: 5`.
2. **41 corpus rows, not 40.** The plan predicted the Node-no-URL-blanking mutation red on "the URL corpus row"; it is
   not: `https://github.com/x/y/blob/main/docs/memory.md` yields nothing even unblanked, because every component follows
   a `/` or `:` the lookbehind refuses or the class lacks. Blanking only matters where a URL holds `@`, `=`, `?`, `&`
   before a path. Added the row `a URL whose query and userinfo name paths`; the mutation then reddens 2.
3. **Added beyond the plan:** a fixture where one old path is renamed twice (`dup.py`), because the plan's fixture
   (each path renamed once) left `py-renames-oldest` GREEN (measured: PASS 125, 0 failures before the fixture);
   `head_print` compared across sides over the fixture repo; Thai-adjacent unit tests.
4. **`e.g` is a raw reference** (the plan's own `test_extract_kinds` expects it); the v5 literal's no-path fact
   therefore has `refs: ["e.g"]`, which resolves to nothing.
5. **Docs/gate edits outside Task 2's file list**: `test_conformance_suite_table_gate.py` and
   `test_platform_assumption_gate.py` fail without a `touch-refs` row and a `platform-checked:` marker on the corpus's
   Windows-path TEXT row; WORDS ended at thirty-one. Heading set to `thirty-three` (touch-log + touch-refs on disk).
