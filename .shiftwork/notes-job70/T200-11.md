## What changed (both runtimes, touch layer only: `touch/log.py`, `touch/log.ts`)

- `TouchLog.bound()` / `bound()` now takes `storage.lock.exclusive(<log>)` itself and does the whole
  fold inside it, **only when `held` is true**. A wait that runs out returns `False` and writes nothing
  (the append already went ahead, as before). Under the lock it re-reads the file, returns `False` when
  it is no longer over `TOUCH_LOG_CAP_BYTES` (another appender folded first), writes
  `bound_body(data)` temp then rename, and carries over verbatim any bytes an unlocked appender added
  between the read and the rename. Returns `True` when it rewrote; never raises/throws.
  It no longer goes through `LogSegment.fold` (whose lock yields `held=False` and runs anyway).
- `bound_body(data)` / `boundBody(data)` (new export, pure):
  1. every `folded` row, and every object line with a string `ts` `<` `fold_cutoff(data)` (the T200-10
     midpoint rule, unchanged), go to `touch_reducer`; other object lines are kept as read, in order;
     non-objects dropped;
  2. if the kept lines alone are over `TOUCH_LOG_FOLD_TARGET_BYTES = 750_000` (no `ts` past the
     midpoint, or `ts` out of order), they are folded too;
  3. **aging rule**: while folded + kept is over 750,000 bytes, folded rows are dropped **oldest `ts`
     first, ties by path in code-point order**; survivors stay in path order, first.
  The result is always <= 750,000 bytes, so every rewrite ends under the cap and the next one waits for
  >= 250,000 bytes of new lines (no thrash).
- **What the aging drops:** a dropped row takes its path's touch count `n` and last-touch `ts` with it
  (the graph and the SessionStart summary forget the paths untouched for longest). In case 2 the newer
  lines' `session`/`seq`/`via`/`from` and their `use` lines are folded away too. Written into
  `docs/touch.md` (*Errors*, log growth row) and `docs/storage.md`.

## Deviations

- Step 1 sends EVERY earlier `folded` row to the reducer, not only those `ts <` the cutoff. A folded
  block is in path order, so its `ts` is out of order; my first version kept half of it as read when
  the cutoff landed inside it, which pushed the kept part over the target and folded the current
  session's live lines (case 2). The Python race unit test caught it under load: 1 of 16 runs, "2
  appends lost" (the race lines were folded into `folded` rows). With the change: 32/32. Monotone logs
  (every existing bed) give the same bytes either way: all 84 T200-10 cases unchanged and green.
- `touch_ref.py`'s `touch-bound` section grew `bodies` and `held` request keys and its own small bed
  runner (`_held_bed`) that delegates `raw`/`bytes`/`append_touch` to T200-1's `_log_bed`
  (that section is not edited).
- Not changed (storage layer, another unit's): Retention's 30-day fold of the touch log still goes
  through `LogSegment.fold`, which runs unlocked when its wait runs out. Retention is off here.
