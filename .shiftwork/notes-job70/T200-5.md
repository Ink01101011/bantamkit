## Deviations from the plan (property kept)

1. **A weak stamp that is not a ledger timestamp is skipped** in `context_weights` (both runtimes), instead of the
   plan's bare `_parse` raising. Python raising would drop the whole context while Node's `parseTs` returns NaN and
   would poison the sum: the two would disagree. Case: `context_weights — a strong and a weak edge ...` (`bad`).
2. **`window` validates rows**: a row whose `seq` is not an integer (an integral float counts, the `touch.graph._seq`
   rule) or whose `path` is not a string is skipped. Rows come from `TouchLog.tail`, which already filters, so this
   only matters for direct callers. Case: `window — malformed seq and path ...`.
3. **`TouchContext` in Node is an interface whose `graph` is `ContextGraph`, spelled in `context.ts`**, not
   `GraphData` from `graph.ts`: `component.d.ts` names `TouchContext`, and `graph.d.ts` reaches `logsegment.d.ts`, whose
   types reach `Buffer` (job66/#144's strict-consumer test). `npm test` includes that test and is green.
4. **`Memory.layer_stores()` / `layerStores()` added** (the plan used `m._layers`): Node's `layers` is private.
5. **`now` is `store.utc_now()`**: the hook's `_stamp()` carries milliseconds, which the usage ledger's `_TS` rejects
   (the plan's own fallback).
6. **The hook beds commit a file.** A repo with no commit has no graph: `touch.repo.renames` reads `git log`, which
   fails without HEAD, so `TouchGraph.load` answers `None` (T200-4 behaviour, not changed here). Found when the first
   hook test came back with no context; probe:
   `git init -q /tmp/x && cd /tmp/x && .venv/bin/python -c "from bantamkit.touch.repo import *; print(renames(find_repo('.')))"` -> `None`.
   For the reviewer: in a fresh `git init` with no commit, `w_context` and the via path are silently off.
7. **The `VIA_ON`-patched hook case runs in-process on the Python side only** (`hookadapter.run_hook(io.BytesIO(...))`
   with `monkeypatch.setattr(tc, "VIA_ON", True)`): a subprocess cannot see a monkeypatch. On the Node side the
   `VIA_ON` branch of `viaEnabled` is covered by `setViaOn` in the module test and by the conformance `via_enabled`
   case (eight env/`VIA_ON` pairs, both sides).
8. **The log record's `context`/`via` fields** ride in the same spread as `skipped` (`degraded`), so every
   UserPromptSubmit record after the recall carries `context` when there is a context, not only the inject one.
   Absent when there is none, so every record written before #200 (and every bed with no touch log) is unchanged.
9. **Step 2 ("see them fail") was not a separate red run**: the tests were written next to the implementation. Every
   guarding case was proven red by the mutations below instead.
