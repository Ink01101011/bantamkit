## Deviations from the plan (property kept)

1. **The layer print is NOT `dumps(shards)`.** The shard prints fingerprint postings, and postings hold only the
   FIELD_BOOST fields (name, description, keywords). `refs` also come from the BODY, so a body-only edit that adds a
   path moves `refs` and no shard: the strong half would go stale. `HotIndex.head_print` dumps
   `{dir_mtime_ns, full_at, shards}`: every refresh that changes a doc moves `dir_mtime_ns` (fast patch) or
   `full_at` (full refresh). Cost: the strong half also rebuilds once per full refresh (every 600 s), two git calls.
   Proof: `test_index_head_print_moves_on_a_body_only_write` (both sides) asserts the shards are EQUAL after the
   body-only write and the print still moves:
   `.venv/bin/python -m pytest runtime-py/tests/test_touch_graph.py -q -k body_only`
2. **The strong print hashes `hotindex.dumps([...])`, not `json.dumps([...])`**, so both runtimes print the same
   string with one serialiser (Python's default `json.dumps` separators have no one-call twin on the Node side).
   Proven by the two cross-runtime freshness cases (a graph one side wrote is not rewritten by the other).
3. **`layers` accepts `(label, store)` or `Memory._layers`' `(label, store, writable)`**; a 2-tuple counts as writable
   only at position 0. A read-only layer whose `docs()` raises contributes `{}`; the writable one raising makes
   `load` return `None` (plan: mirror `_pooled`). A layer whose index `dir` is not a directory prints `-` and
   contributes `{}` without refreshing, so no empty index is written for a missing native directory (test
   `a_missing_layer_directory...`; a `MemoryStore` creates its root, so that test uses a `NativeStore`).
4. **`strong_print`/`weak_print` are public** (plan: `_strong_print`/`_weak_print`): the conformance ref calls nothing
   private.
5. **An integral float `seq` (`2.0`) counts as `2` in Python**, as `JSON.parse` reads it in Node (`_seq`); a bool never
   counts. Same rule for `version` when a graph file is read.
6. **The graph file is shape-checked on read** beyond the key set (prints strings, `files` a list, `strong`/`weak`
   objects); anything else is rebuilt.
7. **Node returns `JSON.parse` of the bytes it wrote**, so a fresh build and a file read are one shape (`Map`s are used
   only while building, for `__proto__` keys).
8. **The "load twice, count ls_files" probe is `load_nogit`**: a load with PATH empty. A side that rebuilds the git
   half on a weak-only change cannot run git there and answers null. No counter hook was added to either runtime.
   The Python unit test monkeypatches `graph.ls_files` as the plan says; the Node unit test empties PATH.
9. **The weak print is compared unmasked** (the plan masks both prints): it is the log size and segment count, which
   the touch-log suite already proves byte-identical, so comparing it is free strength. Only `strong_print` is masked.
10. **Step 2 ("run them and see them fail") was not observed as a separate red run**: the tests were written next to the
    implementation. Every guarding case was instead proven red by the mutations below.
