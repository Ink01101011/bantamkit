## The change (both runtimes, same unit)

- `WIDTH = 80` and `ELLIPSIS = "…"` in runtime-ts/src/statusline.ts and
  runtime-py/src/bantamkit/statusline.py, plus `columns()` (the three state emoji count 2, all
  else 1: the line can only hold ASCII, U+00B7, U+2026 and those three).
- `render`: build the full line; if it fits, return it unchanged (so every line that already
  fit keeps its bytes). Otherwise shorten the TOOL name only, to fit exactly, ending in `…`; the
  outcome (closed vocabulary, what the operator acts on) is never shortened. Deterministic:
  pure function of the reading. Worst case leaves 6 tool characters (64-char tool, degraded,
  50/50, `empty-unreadable-layer`), so the cut never empties the tool.
- Unknown lines are at most 43 columns; untouched.
- docs/statusline.md: new section "The width: at most 80 columns" (and 3 rows in the
  non-vacuity table). Notes the U+00B7/U+2026 East-Asian-Ambiguous caveat.

## Pin moved (issue outranks a pin that contradicts it)

`test_the_degraded_line_names_the_most_recent_problem_not_the_most_recent_record` (py) and
`the degraded line names the most recent PROBLEM, not the most recent record` (node) pinned
`... 3 events · 1 problem · memory_recall empty-unreadable-layer`, an 83-column line #189 says
must not exist. Old contract: no width bound. New: `memory_re… empty-unreadable-layer`. The
test's own property (names the problem, not `validate_json valid`) is still asserted; a comment
citing #189 sits on both.

## Open questions

1. UX choice: the most common real degraded line (`memory_recall empty-unreadable-layer`)
   is now always cut (`memory_re…` / `memory…`). The issue's alternative — a compact degraded
   form (e.g. dropping `N events ·` when degraded) — would keep the tool whole for every real
   bantamkit tool name, but rewrites the documented degraded format and moves more pins. I took
   the smallest change that holds the property; the user may prefer the compact form.
2. The 80-column bound is stated for the one-column setting of East-Asian Ambiguous characters
   (U+00B7, U+2026), documented in docs/statusline.md.
