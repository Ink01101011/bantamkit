## 2. What changed

The sentence, one byte-identical string on both sides, after the SDK prefix:

    Error executing tool <name>: unknown argument '<key>'; known: <keys in schema order, ", "-joined>

- `known: (none)` for the two tools with no argument (`build_identity`, `bantamkit_status`).
  The brief's "comma-separated" has no spelling for an empty list; an empty tail
  (`known: `) reads as a truncation, so `(none)` was chosen. Open question Q1.
- The FIRST unknown key in arrival order is named (both sides keep JSON object order).
- Order of checks: lone surrogate (#160, even inside an unknown key's value) -> unknown key ->
  JSON-string unwrap -> type/missing checks. Same `isError: true` result envelope as every
  other argument refusal; the handler never runs, so nothing is done.
- **Reference** (`runtime-py/src/bantamkit/mcpserver.py`): `_ArgMetadata.validate_arguments`
  override, raising `ValueError` before `super().validate_arguments`. `Tool.run` wraps it in
  `Error executing tool <name>: `. NOT `extra="forbid"` (which the brief's file list names):
  that is pydantic's `extra_forbidden` frame, listing every extra key AFTER the type errors,
  so the user's one-sentence ruling could not be held by it. `known` is the arg model's field
  order (alias when set).
- **Port** (`runtime-ts/src/mcp/pyargs.ts`): `unknownArgument(model, args)`, called by
  `validateArguments` right after `loneSurrogateArgument`. `known` is `model.fields` order.
  The server dispatch (`server.ts`) needed no change: it already prefixes every non-`Unknown tool:`
  error with `Error executing tool <name>: `.
- **Assets**: the 14 served `assets/tools/*.json` close `parameters` with
  `"additionalProperties": false` (top level only; agent-only and retired assets untouched).
  `runtime-py/tests/data/served-tool-surface.json` gains the same 14 leaves;
  `runtime-ts/test/packaging.test.mjs` byte literal `248565 -> 249055` (+490 = 14 x 35 bytes),
  measured off the assertion's own failure `249055 !== 248565`.
- **Order tie**: `known` comes from each runtime's argument model; a test on each side asserts
  the model's field order equals the asset's `parameters.properties` order for all 14 tools
  (`test_the_known_list_is_the_asset_order_and_the_signature_order`,
  `every served model lists its fields in the asset order`), and the conformance literal reads
  `known` off the asset on disk.
- `docs/mcp.md`: one paragraph under "What's exposed".

Pins that moved: none edited. `argument-refusals` id 28 and `memory-compact` id 21 now carry the
refusal on both sides; they are differential cases and stayed green without edits.
