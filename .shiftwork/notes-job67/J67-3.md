## What the user's ruling (2026-10-15, register (yyy)) asked for, and what landed

(a) **save skips an unreadable fact file by name — BOTH runtimes.**
`MemoryStore.save` (store.py / store.ts) now reads `facts/` through the tolerant listing
(`_facts(skipped=...)`, the #119 seam recall already used). A file it cannot read is left out
of the duplicate check, named in `SaveResult.skipped` (`{file, reason}`, reason = the store's
own `malformed fact file …` sentence), and the save lands. The index it measures and rebuilds
is built from the facts it COULD read (`_index_text(tolerant=True)` / `indexTextOf(true)`,
save path only; `index_text()` / `indexText()` stay strict). Two decisions of mine, stated:
- **A save never overwrites a file it cannot read.** Saving under the skipped file's own name
  is refused: `<reason>; saving '<name>' would overwrite that file, so nothing was saved -- repair it or move it out of facts/ first`.
  Without this, a Node save of `zz-anchored` would silently replace a hand-edited file Python
  reads (Python would update it, keeping `created`). Same sentence on both sides.
- **`Memory.save` names the skip** with the recall paragraph's shape:
  `saved 'x'\n\n1 fact file could not be read and was skipped; the duplicate check read every other fact:\n[project] <reason>`
  (also appended to a `duplicate` reply). `SaveOutcome.status` is unchanged (`saved`).
- Node's `SaveResult.skipped` is OPTIONAL (absent when nothing was skipped) so every existing
  result keeps its shape (two `store.test.mjs` deepEqual pins proved the shape is pinned); in
  Python it is a defaulted dataclass field `()`, equality-compatible.
- The component's bent-name pre-check `lookup(name, stamp=False)` is tolerant too (`skipped=[]`),
  else it would re-raise before the save.
The same outcome on Python: for a file BOTH refuse (truncated, non-UTF-8) the answers and the
tree are byte-identical side to side. For one of the eight ruled shapes, Python reads it and
Node skips it: the save lands on both, the written fact is identical, and only the skip list,
reply paragraph and index line differ — ruled (`store.mjs`).

(b) **blank lines inside a block sequence are READ** (factfile.ts only; Python is PyYAML):
blank lines, lines of spaces and comment lines between items, before the first item, after a
block-scalar item, and a `links: ` / `links: # c` line before the sequence. Plus one
plain-scalar fix the shape needs: a continuation line that is only spaces (or spaces + a
comment) ENDS the scalar when the next content line is not a continuation (PyYAML reads
`- a\n  \n- b` as `[a, b]`; the port used to refuse "a blank line inside a plain scalar").
A blank line FOLLOWED by more continuation text (PyYAML folds it to `\n`) is still refused by
name — not in the ruling, see open question 1.
There was no `ruling:` case for this shape to move (the 8 ruled cases are anchor, `!!str`, flow
mapping x2, nested/pair/two-line flow sequence, anchored item; register (yyy) listed it in prose
only), so it lands as 12 new read-alike cases (parse + stamp bytes, side to side, plus the
existing per-side "reads every read-alike input" literals) and a second seeded corpus.

(c) **the eight ruled shapes stay refused by name, as the final answer.** Their `ruling:` cases
and per-side literals are untouched; the comment above them in codec.mjs and the porting.md
row now say "final answer" and point at the save behaviour.

(d) **#176.** `validate()` and the exported `iterErrors()` refuse a non-`PyValue` with
`jsonschema seam: <the instance|the schema> must be a PyValue — convert a plain JS value with fromJs() — got <a plain JS object|a JS array|a JS string|undefined|…>`.
`formatFact` also accepts `parseFactText`'s `{meta, body}` and maps it as `_facts` does
(`name`/`description`/`type` required — a missing one is a named `FactParseError`:
`formatFact: the frontmatter has no 'name' key, and a fact must carry name, description and type`;
`links` = `list(meta.get("links") or [])`). `pyTruthy`/`pyList` moved from store.ts to
factfile.ts (one copy, store.ts imports them). New type export `ParsedFact`.
Interpretation of "round-trips for every x parseFactText accepts": for every x the port parses
that carries the three required keys, `formatFact(parseFactText(x))` equals the bytes the
reference writes back for x (`codec_ref.py reemit`) — fuzzed over 2109 inputs, 0 misses. An x
missing a required key gets the named error, matching the reference's KeyError (it is not a fact).
