# J72-18 — probe F: lexical-evidence veto and rerank over B's candidate list (implementer claude-opus-5-5)

VERDICT: **refuted.** No probe-F policy meets either bar shape on dev, and none passes a single bootstrap resample
(0/5 on both shapes for all 27 grid points). The best point, F1-k3-tq50, fails r@3 even when all 4 of its unjudged
pairs are counted positive (upper r@3 0.4095 against a target of 0.4242, and 0.4142 on the gold shape). The prime
suspect is wrong: the Thai evidence features are **anti-informative** (AUC < 0.5) on prompts that carry any latin
token. The one useful feature, latin_idf (AUC 0.69), mostly duplicates what s already ranks by.

Read-only on product code. **No gold look**: gold labels were not read and `gold-looks.jsonl` was not touched. No
ollama call, no embedding, no local model. Selection was on dev, with labels = dev-labels-merged plus the J72-12 fold
(31 rows); the J72-16 and J72-17 slots are empty.

Tracked: this note and `J72-18-scripts/` (probe18.py, post18.py, targets18.py). None of them holds prompt, fact,
path or label text. Untracked and private: `cache/J72-18-results.json` (features, injects), `J72-18-unjudged.jsonl`,
`J72-18-judge-targets.q1.jsonl`.

**Post-hoc only, not eligible.** A latin-only veto (keep iff latin_idf ≥ t), suggested by the Thai AUC below 0.5:
- t = eps: p 0.2789, r@3 0.3864, 147 injected, 19 unjudged
- t = q25: p 0.2966, r@3 0.4019

Both are below the target.

**Why the veto cannot win.**
- A veto only gains r@3 when a positive at rank 4+ survives while wrong top-3 candidates are dropped. Only
  F1-k3-teps/tq25 do that, and only once each (+1/−0).
- A threshold strict enough to lift p (tq50) also drops 4 top-3 positives and empties 8 rows.
- latin_idf's 0.69 AUC is largely the same evidence s already sorts by: s's own AUC is 0.62–0.64, and the per-prompt
  latin_idf AUC is 0.66. So the veto removes no class of error that s keeps.

- **Judging these cannot change the verdict.** With all 4 pairs positive, F1-k3-tq50/F4 reach p 0.3381 but r@3 only
  0.4095. That is below both 0.4242 (bar) and 0.4142 (gold shape).

## 4. Cost
There is no winner, so no hook timing was taken. Estimate for F1-k3-tq50:
- latin_idf, thai_idf and cov need the query terms' idf and, per candidate, which query terms it holds. Both are
  already in the pooled `Columns` (df) and the run-length segments that `bm25_segments` walks. That is one more pass
  over the same segments, so the cost is at most one BM25 scoring pass.
- thai_run needs the same per-candidate presence bits plus the query's run structure (O(|q|)).
- `field` is the one feature the index cannot answer, because the postings keep Σ boost per term, not per field. It
  would need the top candidates' field text (a fact parse each), or a per-field posting, which is an index format
  change.

## Gates and deviations
- No product code or tracked tool changed, so pytest, npm and conformance were not run. The orchestrator ruled
  "both runtimes + conformance" and the silver clause out of scope for this read-only, dev-selected probe.
- `.venv/bin/ruff check .shiftwork/notes-job72/J72-18-scripts/`: All checks passed. This is after `--fix` of one import

- Deviation: the brief's "field: name/description/keywords vs body only" assumes a body field that BM25F does not have
  (FIELD_BOOST covers name, description and keywords only). `field` was read as a name/keywords match vs a
  description-only match. This was decided before any number existed.
- Deviation: F2's "s restricted to field matches" was implemented as two points, F2-field (veto) and F2-fieldfirst
  (field matches first). F3 was also run on plain B (F3B), and F4 was added (BEST F1 + BEST F2-cov). This was fixed
  before the first run, and the total stays at 27.
- Choices made after seeing numbers: all of `post18.py` (the per-prompt AUC, the latin/no-latin split, and the 2
  latin-only veto points), plus the self-exclusion fix in targets18.py. The first draft's glob also matched its own
  output file on the second run.
- As in J72-12/16/17, probe18.py runs on `.venv` with numpy through PYTHONPATH, without `-I`, from the scratch cwd.
