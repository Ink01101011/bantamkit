## 3. Merge helper
`python3 -I $P/J72-8-scripts/merge_dev_labels.py $P` (stdlib only), which writes `$P/dev-labels-merged.jsonl`.
- It reads `J72-9-labels.q*.jsonl` (`{id, positives}`, one row per target prompt) and folds it into
  `J72-6-labels.q1..q4`.
- Each output row is `{id, positives, judged}` for all 60 dev ids. `judged` is the old pool plus the new candidates, so
  J72-10 can count unjudged pairs without the provenance file.
- Before anything is written, it asserts:
  - exactly one label row per J72-9 target row;
  - each new positive is one of that row's new candidates;
  - the new candidates are disjoint from the old pool;
  - **no earlier label changes**: for every id, `merged.positives & old_pool == old.positives`, and no old judged name
    is dropped. It re-checks this on the file after reading it back.
- Probed on scratch labels (`--labels-dir`, `--out`):
  - Random 30% labels merge to 60 rows: 91 earlier positives, 82 new pairs, 24 new positives, 115 merged, 929 judged.
  - A label row naming an earlier-pool fact is refused: "id 1001: a J72-9 positive is not a J72-9 candidate".
  - A missing row is refused: "J72-9 target prompt 1059 has no label row (1 missing)".
  - Run on the real notes dir before the judge, it refuses with "no J72-9-labels.q*.jsonl", and no file is written.
