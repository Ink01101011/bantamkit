## The change (both runtimes)

**A DERIVED cache, `<index dir>/<sha16(root)>.qterms.json`.**
- Format: `{"facts":{name:[tokens,[term,count,...]]},"sidecar":<sha1 of sidecar bytes>,"v":1}`.
- It lives under `BANTAMKIT_INDEX_DIR`, or `~/.bantamkit/index` when that is unset. Deleting it loses nothing.
- It is used only when its `sidecar` matches the sha1 of the sidecar's current bytes. Otherwise it is rebuilt from the
  sidecar and written temp-then-rename. The write is best-effort: if it fails, the rows are still returned.
- Validation is the same on both sides:
  - counts are whole numbers in [0, 2^53)
  - a BOM is refused
  - the first occurrence of a term wins
- Python writes it with `json.dumps(ensure_ascii, sort_keys, compact)`. Node writes the same bytes; a fuzz test pins
  Node against `dumpJson`.
- The sidecar `{"v":1,...}` format is unchanged.
- Documented in `docs/storage.md`. There is no divergence, so `docs/porting.md` has no row.

**Scoring path.**
- `bm25_rows`/`bm25Rows` is `bm25_scores` over rows that are already tokenized. `bm25_scores` now calls it.
- `QueryScorer` receives rows; a fact with no entry is `None`/`null`.
- Q2/Q3 arithmetic, `QUERY_WEIGHT`, `HEAD_SHORT`, `HEAD_CUT` and `TAIL_BYTES` are unchanged.

**Node-internal fast paths with no observable surface.** Each one is tested against the previous code or the table as
the oracle (`runtime-ts/test/queries.test.mjs`). Python is unchanged apart from the cache.
- the `nospace` comparison chain (all 0x110000 code points checked)
- the `stripNospace` code-unit regex
- `tokenizeV2`: sliced spans plus an ASCII `[a-z0-9]+` fast path (fuzz plus every ASCII unit)
- the `JSON.parse` sidecar read when the text ends with a top-level `"v":1`
- `dumpTerms`
- `CountsView` (in place, first occurrence wins)
- direct postings in `bm25Rows`

## Conformance (recall-queries, case 23) and mutations
**New cases:**
- missing-is-built: python and node bytes are identical; the cache is ASCII and carries the sidecar's sha1 and v 1;
  a layer with no sidecar gets no cache
- cross-read: each side reads the other's cache (inode and mtime unchanged) and ranks as its own
- stale-is-ignored: a fact that only stale queries held is not injected, and the cache is rewritten
- malformed-is-rebuilt and deleted-is-rebuilt: the cache comes back byte for byte

- The trace now records the tokenized rows the scorer is handed.

## Deviations and notes for the next unit
1. **Deviation:** the "unindexed" mode wipes the index dir, and the cache lives there by the brief's rule. So that
   mode measures a full cache REBUILD on every run, which is the worst case.
2. **Out of scope, not fixed:** the existing Node sidecar reader (`docOfBytes`) decodes with a BOM-stripping
   `TextDecoder`, while Python keeps the BOM and refuses the file. That makes a possible parity gap for a sidecar
   that starts with a BOM. Untested and unchanged; the new cache reader keeps the BOM on purpose.
3. The p90 of per-prompt diffs is still above 5 ms in both modes. The bar is p50 only.
