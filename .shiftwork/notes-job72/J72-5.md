## 1. Sampling (`dev_sample.py`, seed **20261020**)
`npvenv/bin/python J72-5-scripts/dev_sample.py ~/.claude/projects $N $P/dev-prompts.jsonl`
- **Corpus and era.** The source is top-level `~/.claude/projects/*/*.jsonl`, with `subagents/` skipped. Only records with
  timestamp <= `2026-10-15T12:11Z` count. That cutoff is the mtime of `silver.jsonl` (19:11 +0700), so every prompt predates
  the frozen stores, as gold's do. Only bantamkit had records after the cutoff (82 of them), and those were dropped.
- **Prompt rule.** The prompt test is `mine_silver.py`'s own, imported: a user record that is not sidechain or meta, has
  non-empty text, and does not start with `<` or `[Request interrupted`.
- **Trivial-prompt filter.** Duplicates by text are dropped, keeping the first. Gold has no other filter, so I added one
  floor only: no prompt shorter than gold's shortest prompt (5 chars).
- **Exclusions.** Every silver prompt text and every gold prompt text is excluded. So is every silver session (49), because
  gold was drawn session-stratified from silver.
- **Project mix.** Gold's project mix (each prompt mapped through its silver session, J68-7's way) is scaled to 60 by largest
  remainder.
- **Selection inside a project.** Projects run in sorted order under one `random.Random(SEED)`. Inside each project the
  selection is `build_gold.pick_rows`, imported: a Thai floor of round(quota × 48/50), then one prompt per session per round.
  The 60 picked are shuffled, then given ids 1001..1060 so they cannot collide with gold ids 1..50.
- **Byte-stable.** A rerun gives the same file: `cmp` is empty, sha1 `dd4caa88…`.

## 2. Pooled candidates
- `cd $R && .venv/bin/python $S/dev_extract.py $P/dev-prompts.jsonl $S $C/rows.json $C/dev-rows.json` runs J72-1's
  `extract.py` walk unchanged (the product's `_pooled` with the recording scorer) on the dev prompts. It **asserts that every
  native's rows equal J72-1's `rows.json` exactly**, so J72-1's cached fact vectors apply. Natives seen: 195/264/179/118 rows.
- `bash J72-5-scripts/run_embed.sh` (`dev_embed.py`, run detached, log in `$S/embed.log`) embeds only the three dense query
  variants: bge-m3 Q0, qwen3-embedding:0.6b Q3 (with its instruct prefix), and snowflake-arctic-embed2 Q4 (chunks, `query: `).
  embed_all.py's `post`/prefix/`chunks`/`query_variants` text is copied verbatim. The output goes to
  `cache/dev-<model>.queries.npz`. J72-1's cache files are not touched.
- `npvenv/bin/python J72-5-scripts/dev_targets.py $P $P/J72-1-scripts` builds the pool. Per prompt it takes the union of the
  top 5 names of four rankings:
  - view B, which is `lib.ordered(bm25, w, bm25 > 0)`
  - each dense config, `lib.ordered(cos, w, cos > 0)`: bge-m3 T0 Q0, qwen3 T1 Q3, arctic T0 Q4
- Store copies use J72-2's rule. The block is text-for-text:
  `diff <(sed -n '/^# --- store-copy rule/,/^# ------/p' $P/J72-2-rescore.py) <(sed -n '/^# --- store-copy rule/,/^# ------/p' $P/J72-5-scripts/dev_targets.py)`
  prints nothing.
- Candidates are sorted, then shuffled per prompt in id order by `random.Random(20261019)`.
- Keys are exactly `{id, prompt, candidates}`, `{name, copies}` and `{description, body}`. No engine, rank or score is written.
  Provenance (which ranking proposed each name, and the four ranked lists) goes to `dev-candidates-provenance.jsonl`, which is
  for the scorer only, never the judge.
- Rerunning gives byte-identical output: part1 `a722d8e6…`, part2 `a690d0a9…`, provenance `33e9eef4…`.

Counts: **847 pairs** over 60 prompts (7..18 candidates per prompt), with 1192 store copies. Names contributed per ranking:
B 264 (some prompts have fewer than 5 BM25 hits), each dense ranking 300. Names only that ranking proposed: B 180, bge-m3 160,
qwen3 164, arctic 125. So **469 of 847 pairs are dense-only**. That is the room a policy that ADDS to B needs.

## Deviations
1. Thai share is 100% against gold's 96%. Gold's Thai floor, applied per project, is met by every project's pool, and
   playground's quota of 2 rounds its floor to 2. The non-Thai pool is small (23 of 251), so the dev set has about 2 more Thai prompts than gold's rate gives (57.6 of 60).
2. The length floor of 5 chars is my reading of "filtering of trivial prompts". Gold's own rule has no length filter, and 5
   is gold's observed minimum. It removed 1 startbiz-ui prompt from the pool (60 -> 59). That shifts the seeded draw, so
   without the floor the file differs from line 5 on (`sed 's/len(x) < min_len/len(x) < 0/'` copy, `cmp`).
3. Dense "top 5" means the top 5 ranked by cosine × layer weight among cos > 0, with no gate. That is a superset of what any
   gate would inject.
4. No gates were run: no product code or tracked tool changed.
