# J72-2: blind judge targets plus the rescore script (implementer claude-opus-5-5)

This unit changes no product code. It writes only under `.shiftwork/notes-job72/`. The data files are untracked
and private: `J72-3-judge-targets.jsonl`, plus the merged files the rescore writes. Tracked: this note and
`J72-2-rescore.py`.

Env for every run: `S=<scratchpad>/j722; export HOME=$S/home USERPROFILE=$S/home BANTAMKIT_INDEX_DIR=$S/index
BANTAMKIT_RETENTION=off TMPDIR=$S/cleantmp/`. The script only reads label, injection and store files. It runs no
engine and no ollama.

## 1. Judge targets
`.venv/bin/python .shiftwork/notes-job72/J72-2-rescore.py targets`
-> `{"unjudged_rows_in": 74, "distinct_pairs": 68, "dropped_already_judged": 0, "pairs": 68, "prompts": 35}`
- Shape: `{id, prompt, candidates:[{name, copies:[{description, body}]}]}`. This is exactly
  `notes-job71/pool-judge-embed-targets.jsonl` (see deviation 1).
- Store copies: J71-5-pool.py's `copy_of`/`copies` code, copied text-for-text. Only blank lines differ:
  `diff <(sed -n '/^def copy_of/,/^    return out/p' .shiftwork/notes-job71/J71-5-pool.py) <(sed -n '/^def copy_of/,/^    return out/p' .shiftwork/notes-job72/J72-2-rescore.py)`
  shows two added blank lines and nothing else. Self-checks run on every `targets` call: the copies equal #199's
  pool targets and J71-5's pool targets, and the merge recipe reproduces J71-5's `pool-{targets,labels}-merged.jsonl`.
- Already judged means: a gold candidate, a #199 pool target or a J71-5 pool target. 0 of 68 pairs were dropped,
  as expected, because J72-1's goldlook computed "unjudged" against the same sets.
- Candidates within a prompt are sorted and then shuffled with `random.Random(20261018)`, in id order. The file
  holds no look tag, engine or score. A grep for G1/qwen/tag/score finds hits only inside verbatim prompt and
  fact-body text, never in keys or metadata. The rerun is byte-stable: sha1 `d7e54c42…` both times.

## 2. Rescore
`.venv/bin/python .shiftwork/notes-job72/J72-2-rescore.py rescore [--labels P] [--allow-unjudged]`
(the default labels path is `notes-job72/J72-3-labels.jsonl`)
- Merge, J71-5's way: target rows are concatenated per id in file order (#199, then J71-5, then J72-3) and ids are
  sorted. Positives are unioned and sorted. Output: `notes-job72/pool-targets-merged.jsonl` and
  `notes-job72/pool-labels-merged.jsonl`.
- Scoring: `tools.eval.recall.score_pooled.score` runs on exactly four views. B_shipped comes from
  `notes-job71/pool-injections-embed.json`. G1, G2 and G3 come from `J72-1-gold-inject-G*.json`. No other policy
  is scored.
- Refusals, each probed:
  - No labels file: `no judge labels at …: run the J72-3 judge first`.
  - A target prompt without a label row: `J72-3 target prompt 14 has no label row (25 missing)`, from 10 rows.
  - Unjudged pairs, probed on a scratch copy with only 30 of the 35 target rows:
    `12 injected pair(s) still unjudged (first: view G1, prompt 45)…`.
  - With `--allow-unjudged`, the same copy prints unjudged counts 7/2/3 and scores those pairs negative, in memory
    only.

## Deviations
1. The brief says candidates are `{name, description, body}`, but the reference file it names
   (pool-judge-embed-targets.jsonl) uses `{name, copies:[{description, body}]}`, because a name can have more than
   one store copy. I followed the file ("exactly the shape of").
2. The target builder is a `targets` subcommand of `J72-2-rescore.py`, not a separate script. That keeps it
   rerunnable while committing only the script and this note.
