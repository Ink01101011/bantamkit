## Change (one commit, d5703bc)
- Ruling followed: Node follows Python. `runtime-ts/src/memory/queries.ts`: `docOfBytes`, `sidecarEntries` and the
  term-cache reader `cached` now decode through `pyDecodeUtf8`. That decoder keeps a BOM as U+FEFF, so the parse refuses
  it and the sidecar is malformed, as in Python. Python is unchanged; its readers (`_doc_of` and `_cached`) were already
  consistent with each other.
- `pyDecodeUtf8` (`runtime-ts/src/memory/pyfs.ts`): the fatal `TextDecoder` (`ignoreBOM: true`) now answers first. The
  CPython-message validator runs only when it refuses. The reason is in "Bench" below.
  - Equivalence check: `node <scratchpad>/j7231/equiv.mjs <c83bb2c copy>/runtime-ts/dist/memory/pyfs.js`.
  - It covers all 1-3 byte sequences, the full F0-FF 4-byte lead space, and a selected-byte 4-byte grid:
    `{"n":64028929,"loop_rejects_td_accepts":0,"loop_accepts_td_rejects":0,"text_mismatch":0}`.
- `new TextDecoder` added in `cf42033..HEAD -- runtime-ts`:
  - `queries.ts` had three; all three now use `pyDecodeUtf8`.
  - **Deviation:** `hookadapter.ts` `previousPrompt` (`fatal: false, ignoreBOM: true`) is left as it is. It ports
    `errors="replace"`, and `pyDecodeUtf8` is strict: routing it there would turn the `head/rules: bad utf-8` case (want
    `ok`) into a throw. It already keeps the BOM, like `mcpreport.ts` and `docread.ts` do in replace mode.
- Unit tests:

  - `a BOM sidecar is malformed: read, ranked and replaced` (node). It goes red on the c83bb2c copy (`fail 1`).
