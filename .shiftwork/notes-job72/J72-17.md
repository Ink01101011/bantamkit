undecided only at the upper bound, and only for D3.
- No D variant meets the bar shape on dev (p >= p(B) + 0.05 AND r@3 >= r@3(B) + 0.01). No D variant passes a single
  bootstrap resample (0/5 for all 11).
- Every D1 variant (9 of them: U1/U2/U3 × λ 0.25/0.5/1.0) is **below B** on both p@inject and r@3. Each loses 3–26

## 2–3. Leakage rule and learned signal (fixed before any number)
**Leakage rule.** An event is usable for dev prompt q only if all of these hold:
- its prompt timestamp is earlier than q's;
- its file stem and its record sessionId both differ from q's session;
- its prompt text equals no dev prompt and no gold prompt text.

Events are deduped by the prompt record's uuid (11 duplicates), keeping the first.

**Learned field.** L(f) is built from the usable event prompts whose U-set contains f:
- newest first, at most 20;
- each prompt cut to 300 chars;
- joined with "\n".

**Score.** s_learn(q) is the **product's** `retrieval.bm25_scores(q, docs)` over the dev prompt's own store rows, in
the walk's row order, with each row as `Doc(name="", description=L(name), keywords=())`. So L is one field with boost
1.0, the product's tokenize_v2 and BM25_K1/BM25_B. The collection statistics are the store's rows. No harness BM25 was
needed.

## 6. Feasibility
**Where the product could get used(fact, turn) going forward.** Read-only look at the real `~/.bantamkit`, with
fields and counts only and no text:
- `hooks/hook-log.jsonl` (461 rows). The UserPromptSubmit `inject` rows carry `session`, `injected` (names), `hits` and
  `prompt` as `{sha256, chars, bytes}`. **No prompt text is logged**, so the log alone cannot build L.
- `usage/<store-id>.jsonl` (1937 events): `{ts, fact, kind}` with kind save 1669 / recall_hit 210 / seed 46 /
  body_read 12, and keywords on save. It has no session and no prompt, so it cannot be joined to a prompt either.
- The MCP server never sees the prompt. Only the hook does: UserPromptSubmit has the prompt, and Stop has
  `transcript_path` (`HookInput.transcript_path`, runtime-ts/src/hookadapter.ts).
- So a learned index would need one of two things. The Stop hook could read the last turn from `transcript_path` (J72-16
  measured a bounded 256 KiB tail read at p50 0.49 ms). Or UserPromptSubmit could persist prompt text per session and
  Stop could join it to that turn's recall/Read events.
- Either way it is a new on-disk store of the user's prompt text, which is a privacy surface that does not exist today.
  It would also be a both-runtimes surface with a conformance case.

- **Size (U2, the largest set), all pre-cutoff events, 20 × 300 cap.** These are the dev stores' row-name sets:

  - trader-platform store: 144 facts, 69.4 KB

  `bm25Scores` p50 1.32 ms / p90 1.83 ms / max 7.67 ms, and Python p50 16.8 ms. That is 60 dev prompts × 21 reps,
  median, with a warm cache.
- An index would carry postings and cost less, but the cost is moot: no variant passes.
