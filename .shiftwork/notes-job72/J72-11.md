## 2. Store copies and the product view B
- `build_kw.py ... <B|A1|A2|A3> $S/v/<v>/stores $P/dev-prompts.jsonl` builds each copy.

- **Finding: both runtimes drop `keywords:` on native (auto-memory) facts.**

  - Node: `runtime-ts/src/storage/hotindex.ts` around line 1128, `keywords: []`.
  - So with the product as it is, keywords written into a native file are ignored. Mode `asis` is the product
    unchanged. Mode `nativekw` is an in-process patch that makes the native hot index read a top-level
    `keywords:` list.

## What shipping A would need (only if the judge clears it), in both runtimes
1. **The native reader must read `keywords:`.** Without it A cannot reach auto-memory facts at all.
   - In both runtimes, the hotindex native `_parse` and `NativeStore._read` change from `keywords: []` to the
     top-level list, validated as a list of strings.
   - That is a new observable surface: a conformance case over a native file carrying keywords, plus a hot-index
     version bump or rebuild, because old indexes hold `[]`.
2. **Save-time keywords.** `memory_save` already takes `keywords`, and the MCP instructions already say "in their
   language".
   - A bilingual instruction ("add Thai and English keywords") is a wording change in the shared instructions
     asset. It is synced to both runtimes and pinned by the instructions gate.
   - No schema change is needed.
3. **Backfill.** Existing facts need keywords written once.
   - Either an operator command that both runtimes would need: generating with a local model is out under the
     "recall must work without embedding/ollama" ruling.
   - Or the dream step run by Claude, which writes keywords through `memory_save`. That fits the ruling, but it
     cannot touch native files. The host owns them, so native facts would need consolidation into the project
     store first.
4. **BM25F weights.**
   - The A3 upper bound (the words also in the description) is worse than A1, so moving weight is not the
     lever. The keyword boost of 2.0 already lets Thai-bigram noise win.
   - If the judge confirms the noise, a weight or IDF floor for no-space bigrams in `keywords` would be the
     question. That is a #199 constant, and **not tuned here; flagged.**
