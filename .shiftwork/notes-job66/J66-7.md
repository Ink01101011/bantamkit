# J66-7 — host install keeps host JSON text: literal UTF-8, original indentation (#118 remainder)

Issue: #118 (reopened PARTIAL by J65-23, register row (vvv)). Role: implementer. Live sibling: J66-4
(mcp protocol B). None of its files were touched.

## 1. Before

J65-18 (9d6466b + ab79a5a) made numbers lossless and refused `1e400` by location. The writer, which
`--install`, `--install-hooks` and `--remove-hooks` all share (`_write_config` / `writeConfig`), still did
`json.dumps(data, indent=2)` / `dumpJson(data, {indent: 2})`. That escaped every non-ASCII character
(`"ไทย"` became `"ไทย"`) and re-indented every file to 2 spaces. Both runtimes did it,
on purpose, and both pinned it: `test_the_written_json_escapes_non_ascii_so_both_runtimes_write_the_same_bytes`
and its Node twin. Mutations M8 and M9 in §4 put that old writer back on both sides and show what it does.

## 2. What changed (both runtimes, one rule)

- **Indent detection.** `_detected_indent` / `detectedIndent` read the target file. They look for the
  first line that starts with a space or tab and holds something other than ` \t\r`. If that line
  starts with a tab, the unit is `\t`. Otherwise the unit is that line's run of leading spaces. With no
  such line (no file, an empty file, or everything on one line) the unit is 2 spaces. Every line start
  is structural, because a JSON string cannot hold a raw newline.
- **Literal UTF-8.**
  - Python writes `json.dumps(data, indent=<unit>, ensure_ascii=False)`. A lone surrogate (from a
    `"\ud800"` in the source) is the one thing UTF-8 cannot carry, so it is re-escaped as `\udXXX`.
    Without that step `write_text` crashes (mutation M3).
  - Node (`hostJsonText`) starts from `dumpJson`'s `ensure_ascii` output at indent 2. One regex pass
    unescapes `\uXXXX` codes at 0x7f and above, plus valid surrogate pairs. It keeps C0 controls and
    lone surrogates escaped, and it consumes `\\` pairs first so that an escaped backslash before
    `u0e01` stays text. It then rewrites each run of 2 × depth leading spaces to the unit repeated
    depth times. `pyjson.ts` was not touched.
- Two spellings are normalised, as documented: an escape the user wrote for a printable character
  comes back as the character, and line endings are written as `\n`.

Open questions:
- Line endings: a CRLF file comes back LF, and a missing final newline gets one. Both runtimes do
  this. It is outside the brief's property and is documented in install.md.
- A user-written `"ก"` escape comes back as `"ก"`. The meaning is kept but the spelling is not,
  because the writer has one spelling per string. Keeping it would need a splice-only writer.
- `docs/roadmap-toolbox.md` row (vvv) still describes the remainder as open. Only J66-12 may edit it.
- Indent detection takes the first indented line as-is. A file with odd formatting (for example a
  first member at 3 spaces) gets 3-space units throughout.
