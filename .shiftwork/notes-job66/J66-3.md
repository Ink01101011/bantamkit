## 2. What changed

**Node — `runtime-ts/src/mcp/transport.ts`.**
- #146/#148 ids: every request (object with `id` and `method`) is handed to the SDK under a
  per-message token `bantamkit-<n>`; the client's id is kept as its exact JSON TEXT (a number is
  re-read losslessly with `pyjson.parseJson`, so an int past 2^53 is exact and a float literal
  is no id). The side table (raw line + exact result) is keyed by token, so two in-flight
  requests sharing an id no longer share a slot. `frame()` writes the id text back. A
  `notifications/cancelled` naming a client id is pointed at the newest token carrying it.
  `rawLineFor`/`setExactResult` keep their signatures; `server.ts` passes `extra.requestId`,
  which is now the token — no server.ts change was needed for this.
- #148 refusals: not JSON -> `{"jsonrpc":"2.0","id":null,"error":{"code":-32700,"message":"Parse error"}}`;
  JSON the schema refuses -> same with `-32600`/`Invalid Request`. Blank lines skipped.
- Aligned to the reference's pydantic reading (so the port does not call Invalid what the
  reference answers): an id that is not str/int -> the frame becomes a notification (nothing
  answered); unknown top-level members dropped; `params: null` dropped. A lone surrogate
  anywhere except a `tools/call`'s arguments (job65/#160's by-name refusal) -> `-32600`, which is
  what the reference now says (pydantic cannot read it; stdlib json can).
- #181: `output.on('error')`: EPIPE/ECONNRESET/EOF/ERR_STREAM_DESTROYED -> destroy stdin, close
  the transport (cli's `onclose` resolves, exit 0); any other error is rethrown (crash as before).

**Python — `runtime-py/src/bantamkit/mcpstdio.py`** (the Python protocol code; `mcpserver.py` itself
was not touched). `_Lines` now also answers `malformed_frame_error(line)`: the SDK's own adapter
decides whether the SDK would drop the line; if so, `json.loads` (NaN/Infinity rejected) decides
-32700 vs -32600. A line spelling `NaN`/`Infinity` that strict JSON refuses is -32700 even where
pydantic would read it (matches `JSON.parse`). Stdin is read on a DAEMON thread (`_DaemonLines`,
one line of read-ahead) instead of `anyio.wrap_file`, and `serve_stdio` catches
`except* (BrokenPipeError, ConnectionResetError)`.

**Harness.** `wire.mjs`/`wire_ref.py` drivers gained a `burst` directive (one write of several
frames, wait for a COUNT of answers, bounded at 10 s so a silent server fails as named missing
frames) and a `hangup` session flag (close stdout after the last line, keep stdin open, 20 s grace,
`exit: null` if it had to be killed). Sessions `j66-3-malformed`, `j66-3-bigid` (also compared by
the per-id loop incl. raw bytes), `j66-3-dup`, `j66-3-hangup`. Stale SDK text `1.30.0` -> `1.31.0`
at server.ts:6 and the two wire.mjs ruling descriptions (as asked by the orchestrator).
