## Parity, established (not taken from the issues)

- #139 is SHARED. Python `_dispatch` was the same sequential if-return as `cli.ts` `main`, and
  `_run_hook` never reads `args` (J65-0 row 139). Fixed in both.
- #140 is NODE-ONLY. CPython 3.12 `rglob` over a missing root, a regular file, or a mode-000
  directory yields `[]`:

      cd <scratch> && .venv/bin/python -I -c 'from pathlib import Path; print([list(Path(r).rglob("*")) for r in ("nope",)])'

  so `BANTAMKIT_ASSETS=<missing> python -m bantamkit.mcpserver --assets-root` already printed
  `<path>` / `0 files`, exit 0. Only `walkFiles` changed.
- #174 is NODE-ONLY. Python is the reference (`type=int`). Measured `int()` on 3.12: Nd digits
  of any script (astral too) and the 19 non-ASCII `isspace()` code points map to ASCII; ASCII
  whitespace is only ` \t\n\v\f\r` (`int('3\x1c')` is ValueError although `'\x1c'.isspace()`);
  U+FEFF is not a space; `_` only between digits; > 4300 digits is ValueError.

## What changed

- **#139 (both runtimes).** `_parse_args` / `parseArgs` refuse two one-shot flags
  (`--assets-root --hook --mcp-report --statusline --update --install --install-hooks
  --remove-hooks`) with argparse's own usage error: usage block, then
  `bantamkit-mcp: error: argument <later-registered>: not allowed with argument <earlier>`,
  exit 2. NOT `add_mutually_exclusive_group()`: measured, CPython 3.14 brackets a
  non-contiguous group in the usage line (`[--assets-root | --hook | ...]`) while 3.12/3.13 omit
  it, so a real group would make `-h` depend on the interpreter minor version; both `-h` outputs
  are unchanged (the cli suite's help cases stay byte-identical). Probe:

      for py in .venv/bin/python python3.13 python3.14; do $py -I <scratch>/J66-6/grp.py; done

  The `--force`/`--yes` refusals moved BEFORE every acting arm (same sentences, same exit 1),
  and `--hook` with `--store`/`--start` is **refused, not honoured**, at exit 1:
  `--store is not meaningful with --hook` / `--start is not meaningful with --hook`. Reason:
  the hook binds the store from the cwd in the host's event; honouring argv would be a second,
  competing store selector on a host registration.
- **#140 (Node).** `walkFiles` returns `[]` when the root is not a directory (stat fails or not
  a dir) and treats `EACCES`/`EPERM` on any `readdir` as an empty listing — `rglob`'s rules.
  `--assets-root` at a missing `BANTAMKIT_ASSETS` now prints `<path>\n0 files\n`, exit 0, same
  bytes as Python. Side effect, also parity: `build_identity`'s digest now skips an unlistable
  subdirectory as Python's `rglob` does instead of answering "unreadable asset".
- **#174 (Node).** `pyIntStrict` is a port of CPython `int(str)`: per-code-point transform
  (Nd -> its digit via the contiguous-run offset, the 19 Python spaces -> ' ', anything else
  non-ASCII refused), then `[ \t\n\v\f\r]*[+-]?D(_?D)*[ \t\n\v\f\r]*`, 4300-digit cap, `-0` -> 0.
  Differential over 21,366 strings (all 680 Unicode-15 Nd digits, 680 mixed pairs, 20,000
  random strings over digits/spaces/`_`/signs/BOM/U+001C/U+0085/superscript, the 4300/4301
  boundary) against CPython 3.12 `int()`: **0 mismatches**.

      node .shiftwork/notes-job66/J66-6-intparity.mjs        # printed: cases 21366 mismatches 0

## Open questions

1. Unicode-version window (#174): Node 25's ICU is Unicode 16.0 (760 Nd code points); the
   reference venv's CPython 3.12 is Unicode 15.0 (680). The 80 digits added in 16.0 parse on
   Node and are refused by 3.12 — and accepted by CPython 3.14 (Unicode 16). Not a deliberate
   divergence, so no porting.md row was written; pinning a 15.0 table in the port would be
   wrong for a 3.14 reference. Ruling wanted if it matters.
2. `PYTHONINTMAXSTRDIGITS` changes the reference's 4300-digit cap; the port hard-codes 4300.
3. Node `Number` loses precision above 2^53 where Python keeps a big int (`--k 99999999999999999999`);
   both serve, the value differs. Not observable in any output found.
4. `--store`/`--start` beside `--assets-root`/`--update`/`--install*` are still accepted and
   ignored (out of #139's scope, which names `--hook`). `--k`/`--index-budget` beside a one-shot
   are likewise ignored.
5. `pyIntOrNull` (the COLUMNS reader, `shutil.get_terminal_size`'s `int()`) still uses the
   ASCII regex — the same class as #174, not named by it; left alone.
6. `stacked` refusals name flags in `-h` (registration) order, not argv order as a real
   argparse group would; chosen because a real group changes `-h` on CPython 3.14.
