## B1: what was wrong, and which side

- Python `_detected_indent` (`runtime-py/src/bantamkit/hostinstall.py`) reads with
  `Path.read_text`, which is universal-newline: `\r\n`, `\r` and `\n` all become `\n`, so a
  CR-only file's 4-space unit is found. Python is the reference and is RIGHT. It is unchanged.
- Node `detectedIndent` (`runtime-ts/src/hostinstall.ts`) split the raw text on `\n` only, so a
  CR-only file was one line, fell back to 2 spaces, and wrote different bytes.
- Fix: `text.split(/\r\n|\r|\n/)`. That is the universal-newline rule. `\r\r\n` splits into two
  breaks on both sides. The docstring says why.
- Every other Node reader on the host-JSON path: `install` (hostinstall.ts:467), `installHooks`
  (:996) and `removeHooks` (:1061) all write through the one `writeConfig` -> `detectedIndent`
  (`grep -n "writeConfig(" runtime-ts/src/hostinstall.ts`). There is no other `split('\n')` in
  hostinstall.ts or cli.ts (`grep -n "split('\\\\n')" runtime-ts/src/hostinstall.ts runtime-ts/src/cli.ts`
  is empty). So the one line fixes all three flags.
- `--remove-hooks` on a CR-only settings file after the fix: `bash $S/remove-probe.sh "$PWD" "$C"`
  prints `py exit=0`, `node exit=0`, `SAME`, and line 2 has 4 spaces on both sides. The script
  installs hooks into a throwaway HOME per side, turns every `\n` into `\r`, then runs `--remove-hooks --yes`.
