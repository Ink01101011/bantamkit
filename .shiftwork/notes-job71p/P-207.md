## Deviations from the spec, and how the plan resolves them

1. **The Scorer's shape.**
   - The spec says `rank(query, pool) -> [(score, fact)]`.
   - Recall is columnar and lazy: `pooled_ranking` scores concatenated Pool columns and resolves only the
     hits to Facts (the hook parses no fact file but its hits).
   - So the plan's Scorer returns a SCORE COLUMN (`column(cols, vecs) -> list[float] | None`), and
     ranking stays `rank_columns`. The observable contract (sorted by score, ties by layer order then name)
     is unchanged.
2. **Where the BM25 call lives.**
   - The brief points at `Memory._pooled` (component).
   - The call is actually `store.py:579` inside `pooled_ranking` (Node `store.ts:699`), reached through
     `pick_hits`.
   - The gate floor and weights are applied in `pooled_ranking`/`rank_columns` (store and retrieval), not in
     component. The plan edits `pooled_ranking`.
3. **The term-hit early return** (`store.py:557`/`store.ts:677`) would drop every Thai-prompt/English-fact
   recall. The dense scorer skips it, and the fallback re-applies it before BM25.
4. **Partial file pools.**
   - `pool_of` keeps only facts holding a query term, while D4 needs every fact.
   - The plan adds `full=True`, used only when the scorer is dense.
   - BM25 over a full pool is provably the same: n, total and df are unchanged, empty rows score 0, and only
     x > 0 is admitted. That is why fallback stays byte-identical.
5. **The embedded text needs description and keywords**, but the index head's `cols` has neither
   (`hotindex.py:974`). The dense path reads line 2 (`docs_unchecked`, `:364`) once per layer per prompt.
   This costs time within the 100 ms budget; the off path does not pay it.
6. **The text separator before keywords** is unspecified. The plan uses a single space:
   `"<name spaced>: <description> <kw1> <kw2>"`, and no trailing space when there are no keywords.
7. **The query cut of 2,000 "characters"** counts code points on both sides (Node `Array.from`), because
   UTF-16 units would split the runtimes on astral text. A conformance case pins it.
8. **Async.**
   - Python is sync (urllib); Node's fetch is async. `recall_outcome`/`recallOutcome` stay synchronous.
   - `Memory.prepare(query)` embeds first (Python sync, Node `await`), and its Scorer is passed in.
   - Node `userPromptSubmit` becomes async (`runHook` is already async). The `memory_recall` scorer is
     prepared in the async handler before the synchronous `runTool`. Node's save and repair embeds are
     queued and flushed by `await memory.flushEmbeds()` in that handler.
9. **The total timeout.**
   - Python's urllib timeout is per socket operation, so the plan wraps the request in a daemon thread
     with `join(150 ms)`, which is a total deadline like Node's `AbortSignal.timeout`.
   - A daemon thread is used because ThreadPoolExecutor workers are joined at interpreter exit and would
     delay the hook process.
10. **Proxies.**
    - Python urllib honours `http_proxy`, which would send fact text off the machine despite D7. The plan
      uses `build_opener(ProxyHandler({}))`.
    - Node global fetch ignores proxy env unless `NODE_USE_ENV_PROXY` is set (Node 24+). This is left for
      the reviewer to check; there is no dependency to pin a dispatcher with.
11. **Mapping fallback reasons.**
    - HTTP 404 → `no-model`.
    - Any other non-2xx, or a malformed body → `unreachable`.
    - A socket timeout or an abort → `timeout`.
    - The spec names only the five reasons.
12. **"Refused once at startup"** means once per PROCESS. `Memory.__init__` counts `refused-host` once.
    Every hook process is its own process, so its log row carries `fallback: refused-host` each prompt.
13. **The status fallback counts** are the MCP server's own recalls (`memory_recall`). The hook's recalls
    run in separate processes, are counted only in the hook-log rows, and the docs say so.
14. **The hook-log `scorer`/`fallback` keys** are written only when embedding is CONFIGURED (on, or a
    refused host). With embedding off, every row is byte-identical to 0.37.0-beta.1, which protects the
    ≤ 5 ms/off contract and every hooks-suite pin. See open question Q2.
15. **The status `scorer:` line** is always printed: `scorer: bm25f` when off. That is the only change to
    the off-path status text, and the tests pinning the whole status text get that one appended line.
16. **The spec's `bantamkit memory embed` does not exist** as a command on either side. It is
    `python -m bantamkit.memory embed` / `bantamkit-memory embed`. The `vectors: run … embed` fix line
    therefore names the runtime's own prog. That is a deliberate divergence: it extends the
    `index-budget-low` remedy row in `docs/porting.md:355` and gets a `wire.mjs` ruling plus an unruled
    case after substitution, following the precedent.
17. **`memory embed` ignores the BANTAMKIT_EMBED switch** (`embed.forced_on()`), so an operator can fill
    the cache before turning embedding on. The host rule is still enforced. Exit 2 covers a refused host,
    unreachable AND `no-model`; the spec lists only unreachable/refused, and a missing model is equally
    unservable.
18. **The CLI takes `common()`** (`--store | --start`, `--budget`) like every other subcommand, so both
    parser-as-data trees stay uniform and the `-h` stays comparable under the existing prog substitution.
19. **The cache keeps stale records**; there is no pruning. Deleting the file loses nothing (§3).
20. **A dim change rewrites the cache** with only the new records. A dim mismatch with the query vector is
    `coverage`.
21. **A non-little-endian Node** reads the cache as absent, so recall falls back. Python byteswaps.
22. **Lone surrogates.** Python hashes with `surrogatepass`; Node's `update(str, 'utf8')` writes U+FFFD.
    The keys differ for such a text, so a conformance case requires the same visible answer, and the plan
    names the fix if the case shows otherwise.
23. **`EMBED_GATE` starts at 0.0** (admit cosine > 0) until Task 5 tunes it. The gate rule is
    `x > 0 and x >= max(EMBED_GATE, min_ratio * best)`: the same `rank_columns`, with the floor swapped.
24. **The start-up fill** is an in-process daemon thread (Python) or an un-awaited promise (Node), not a
    detached child. "Never blocks startup" holds either way.
25. **The eval's `engine="embed"`** is added to `layered_for_eval`. `tune_embed.py` rebinds
    `retrieval.EMBED_GATE`, so `CosineScorer.floor()` reads it at call time.
26. **A unit for the bar.** Task 5 Step 1 (declare the bar) is split into its own unit, J71-5a, in wave 1,
    so the bar is committed before any embed number can exist.
