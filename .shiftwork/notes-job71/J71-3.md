## Deviations from the plan
1. `fill` builds texts from `store.pool([], full=True)` + `pool_texts` (J71-2's handoff), not
   `store.candidates()` + `embed_text`, and walks layers with `_pooled`'s native shadow, so it
   embeds exactly the rows a dense recall pools. `coverage` walks the same rows.
2. Save/repair embed the fact as the store re-reads it (`lookup(..., stamp=False)` -> `fact_text`),
   not the caller's `(name, description, keywords)` tuple, so the key is the one recall asks for.
3. Node `server.ts` flushes after ANY tool call that queued (only save and a repairing recall
   queue), not by tool name.
4. Conformance Python CLI/server spawns set `PYTHONPATH=<tree>/runtime-py/src`: the venv's
   editable install is bound to the main tree, so on an rsync copy M3b would otherwise test the
   unmutated CLI.
5. Save tests live in `test_memory_vectors.py` (plan listed `test_memory.py`).
6. memorycli header's total ruling count ("29") was already stale before this unit (run prints 35
   ruled); left as is, only the per-family 5 -> 6 counts were updated.
7. Python memory CLI exit-code docstring (both CLIs' headers) extended: 2 also covers `embed`'s
   unusable backend.
