## Deviations from the plan
1. Case 11 (lone-surrogate description) is NOT landed as a scorer case: a fact whose YAML
   description is `"release \ud800 notes"` makes the PYTHON hot index raise `UnicodeEncodeError`
   in `hotindex._write` (`tmp.write_text(..., encoding="utf-8")`, hotindex.py:713) before any scorer
   runs — a pre-existing storage-layer bug, out of this unit's layer, NOT fixed here. Rerun:
   bed with that fact, `.venv/bin/python tools/conformance/ref/embed_ref.py` op `fill`. Lone-surrogate
   keys stay pinned by J71-1's embedKey case.
2. M2e needed a no-shared-token query (above); the plan's claim "no fact shares a token with the
   query except release-notes" is false for Thai bigrams.
3. Node `RecallOutcome.scorer`/`.fallback` are OPTIONAL fields (absent on `recallFile`'s outcome);
   Python's dataclass defaults are `"bm25f"`/`None`. Every `recallOutcome` return carries them.
4. Node `injectCandidates`/`rankAll` take an optional `scorer` (default BM25F) instead of preparing,
   because they are synchronous and `prepare` is async in Node; no Node caller exists (eval is Python).
5. Node `CallTool` handler: no await off-path (the handler returns synchronously unless embedding
   is on), so the off path is exactly as before.
6. `divergence.NOT_A_STORE_ENV` register (above): the guard scans every `bantamkit/memory/*.py` for
   `BANTAMKIT_*` constants and would otherwise demand the embed switch be a store lever.
7. Python `config_from_env(env=None)` reads `os.environ` at call time (plan default `os.environ`).
8. Python `embed_texts` also rejects non-finite numbers (NaN/Infinity tokens `json.loads` accepts and
   `JSON.parse` refuses), so both sides classify such a body as `unreachable`.
9. The ref's `fill` op is a hand fill (Task 3 owns the product `fill`): `store.pool([], full=True)` ->
   `pool_texts` -> `embed_texts(forced_on())` -> `write_vectors`; Node mirrors it in the suite.
