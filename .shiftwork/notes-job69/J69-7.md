## Deviations (code wins; property kept)

1. **Placement.** The plan names the lines but not where; they go after line 6 (no earlier line
   moves) and before the problem block (still appended last, as docs/status.md says).
2. **`<docs> docs` is pluralised** (`1 doc`), as every count in the report is (`_plural`).
3. **`<short-source>` is the layer KIND** (`project`/`extra`/`profile`), never a path or a grant
   name — the report's existing KIND-NEVER-NAME rule. Two extras print two `extra` lines.
4. **Index lines cover the server's memory layers only.** The server holds no native (tier 3)
   hot index; the plan's "one line per hot index" is read as "per index the server holds". A
   layer whose `facts/` is not a directory gets no line (the unreadable-layer condition reports it).
5. **The report refreshes each layer's index (`refresh("fast")`)**, as recall does, so the line is
   deterministic across runtimes (a read-only view diverged in wire: python's recall later in the
   same session built what node's status then saw). Cost: one dir stat per layer, or a build when
   none exists — on demand only, never on the per-call footer path.
6. **`bytes`** = head + every shard file present on disk (0 when in-memory); a log's `bytes` = live
   file + rotated segments; `skipped` = `LogSegment.read().skipped` (reads the whole log, on demand).
7. **Logs listed**: `hooks/hook-log.jsonl` and `usage/*.jsonl` (the LogSegment logs retention
   folds). The event log keeps its own `event log: on|off` line and own `.1` rotation (J69-4 D1).
8. **`retention: off; …`** — an `off; ` prefix when `BANTAMKIT_RETENTION` opts out (the operator's
   state today); the record's `error` key is not printed.
9. **Hook tier reads project scope too** (`<cwd>/.claude/settings{,.local}.json`); hostinstall
   only ever writes user scope, but Claude Code registers hooks from both.
10. **Not a degraded condition.** `in-memory` and missing tiers never flip line 1 or ride the
    footer (S2: tiers 2/3 absent silently; the spec row says "reported by bantamkit_status").
11. Python `storage/__init__` re-exports `status_lines` only: re-exporting a function named
    `tiers` shadowed the `storage.tiers` submodule (caught by `wire`: `'function' object has no
    attribute 'status_lines'`).
