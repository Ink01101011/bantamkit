## Interface as built

The Python names are listed first. Node uses camelCase and the same values.

- `exclusive(path, wait_ms=2000, stale_ms=10000, poll_ms=5)` is a context manager that yields `held`.
  - On Node it is `exclusive(path, body: (held) => T, {waitMs, staleMs, pollMs}): T`, because Node has no context
    manager.
  - The poll is `Atomics.wait`, as J68-4 did it.
  - When the wait runs out, the body runs unlocked, as hookadapter's did.
- `LogSegment(path)` has these members: `.path`, `.skipped`, `.segments()`, `.append(obj) -> bool`, `.read()`,
  `.fold(older_than, reducer)`, and `.rotate(max_bytes=ROTATE_BYTES) -> bool`.
- `dumps_line(obj) -> bytes` (Node: `dumpsLine`).
- `ROTATE_BYTES = 1_000_000`.

## Deviations from the plan (code wins, the plan's property is kept)

1. **The line format is J68-4's, not the plan's snippet.** The snippet's `_line` would raise `UnicodeEncodeError` on a
   lone surrogate, accept `NaN`, and skip blank lines without counting them. The code now does what usage does:
   - it escapes a lone surrogate the way `JSON.stringify` does;
   - it refuses `NaN` and `Infinity` on read, which counts as a skipped line;
   - it splits on `\n` only;
   - it decodes with `errors="replace"`;
   - it counts a blank middle line as skipped;
   - an append onto a cut last line writes `\n` first, as J68-4's M7 did. It reads only the last byte, not the
     whole file.

   These are what let usage move onto `LogSegment` with no rewrite.
2. **Non-finite numbers on write.** Python uses `allow_nan=False`. Node uses a `JSON.stringify` replacer that throws.
   On both sides `append` answers `False`. Without this, Node would write `null` and Python would write `NaN`.
   No conformance case can cover it, because `NaN` cannot cross the JSON harness. It is pinned by a unit test on
   each side.
3. **Fold keeps newer lines AS READ.** The plan's snippet re-serialised them. Re-serialising respells numbers on each
   side differently (`1.0` against `1`, `1e-7` against `1e-07`), which is J68-4's deviation 5 again. Only the
   reducer's output is serialised. Mutation M9 shows the difference is live.
4. **`ts` comparison.** A row is old only when `ts` is a string and `ts < older_than`. The plan's `str(r.get("ts",""))`
   would have turned a numeric `ts` into `"5"` on one side and `5` on the other. A missing `ts` would have counted as
   old.
5. **Missing log.** `fold` and `rotate` on a missing log return at once and create nothing. Otherwise they would spin
   for the 2 s lock wait, as in J68-4's deviation 8. `rotate` on an empty live file answers `False`.
6. **Writes go temp-then-rename.** `rotate` writes the `.gz` with temp-then-rename, then empties the live file.
   `fold` also uses temp-then-rename.
7. **Error handling.** `fold` swallows only `OSError` (Node: an error that has a string `code`). A reducer that throws,
   or that returns a non-JSON row, still reaches the caller on both sides.
8. **hookadapter is not touched.** The plan says the lock is "lifted from usage and hookadapter", but Task 1's Modify
   list names only usage. hookadapter's own copy moves in Task 4, with the logs.
9. **`read(since)`.** Spec S3 lists `read(since)`, but the plan's Task 1 interface has `read()`. I followed the plan.
   This is listed under the open questions.

## Open questions

- **`read(since)`.** Spec S3 names `read(since)` and the plan's Task 1 does not. Should Task 4 or Task 6 add it when a
  consumer needs it?
- **Comparison is not the same for every string.** The fold's `ts < older_than` compares UTF-16 code units on Node
  and code points in Python. They differ only for strings that mix astral characters with U+E000..U+FFFF. Timestamps
  are ASCII, so this is not guarded.
- **Numbers and keys outside the format.** `append` of a float such as `1.0` or `1e-7`, or of an object with an
  integer-like key (`{"b":1,"1":2}`, which JS reorders), writes different bytes on each side. This is the caller's
  object, not the segment, and the ledger formats it avoids are J68-4's. It is not guarded. Should Task 4 pin it
  when the hook log and the event log move on?
- **Windows.** The lock and rename path is still unmeasured on Windows. That is Task 8's manual step.
- **A circular-import hazard.** `memory/usage.py` imports `..storage.lock`, which runs `storage/__init__`, which now
  imports `hotindex`. If `hotindex` imports `bantamkit.memory.*` at module top, and that chain ever imports `usage`,
  the import becomes circular. It is fine today: the full pytest run and `--all` are green.
