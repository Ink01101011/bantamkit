## What landed

**HotIndex, version 2 (user ruling A).** `storage/hotindex.{py,ts}`:
- HEAD `<sha16>.json`: `{version:2, kind, source, dir_mtime_ns, full_at, files, docs, skipped, loose, df, avgdl,
  fingerprint, shards}`; `shards = {"postings": [16 fps], "words": [16 fps]}`, `fingerprint` = sha16 of `dumps(shards)`.
- Shards `<sha16>.postings-NN.json` and `<sha16>.words-NN.json`, each `{"fingerprint", "terms"}`;
  fp = sha256(dumps(terms))[:16]. `shard_of(term)` = `int(sha256(utf8(term)).hex[:8], 16) % 16`, pinned per side
  (`release`→12, `ปล`→0, `😀`→4, `''`→2, `a`→2, `tag`→6, `loose`→6).
- `postings` = J69-2's tokenize_v2 postings (for J68-5). `words` = the store's v1 `tokens(name + " " + description)`
  inverted to names: today's recall score, so recall answers from the index EXACTLY as from the files. The `words`
  family goes when J68-5 moves recall onto `postings`. (Deviation: a second shard family; the ruling named only
  `postings-00..15`. v1 tokens cannot be derived from v2 postings: `[a-z0-9]+` vs NFKC/bigrams.)
- A shard that is missing, not JSON, or whose fingerprint is not the head's = missing index → full rebuild.
  A reader loads the head plus only the shards its terms hash to (`query(terms)`, `query_words(words)`);
  `postings()` loads all 16. `INDEX_VERSION` 1 → 2: a version-1 single file is rebuilt, never read as a head.
- Writes: shards whose fingerprint moved (all after a build), then the head, temp+rename under `exclusive(head)`.
- A patch re-derives postings/words/df/avgdl ONLY when a doc's name/description/keywords or the doc set moved:
  a recall's stamp rewrites the head and no shard.
- An unchanged head file (mtime_ns, size, ino) is not re-read (long-lived server: warm recall ~1.3 ms at 5,000).
- Doc shapes are checked lazily: `docs()` and every patch check them all (malformed → rebuild); the fresh path reads
  only its hits through `doc(name)` (checked one by one). 5 ms of 14 at 5,000 facts in Python.
- `INDEX_DIR_ENV = "BANTAMKIT_INDEX_DIR"`: where `MemoryStore.index()` keeps indexes instead of `~/.bantamkit/index/`.
  Lives in `storage/hotindex`, not `memory/`: it moves an index, never a store, so `divergence`'s writer-env register
  (`test_no_environment_variable_moves_the_writers_store_behind_this_resolvers_back`) correctly does not count it
  (it went red when the constant sat in store.py; moved, green).

**MemoryStore through the index** (`memory/store.{py,ts}`):
- `index()` lazily (`HotIndex(root, "facts", home, index_dir=env)`); `_indexed()` = probe the listing (open+close the
  dir; raises the store's exact `memory store is unreadable` sentence; `False` for an absent `facts/` → files, no
  index file made), `refresh("fast")`, and refuse the index (→ today's file read) when `skipped` or `loose` is
  non-empty, or inside `snapshot()` (Python).
- `recall`: score = count of query words whose `words` list holds the name; same gate (`min_ratio * best`), same
  `(-score, name)` order (Python: code-point sort then stable sort by score desc; Node: top-k insertion for
  0 <= k <= 64, full sort otherwise), same `[:k]`; only the k hits are parsed. A hit whose file no longer says what
  the index said → the files decide (full read).
- `lookup`: `name in index` (miss answers None), then parse that one file.
- Write-through `_after_write()`: refreshes an EXISTING index (never creates one); called at the end of
  `_rebuild_index` (save + rollback, compact, archive, restore), after recall/lookup stamps, and in `dream` for both
  stores. A refresh that raises → in-memory index dropped, next reader patches from disk.
- Python libyaml: `load_frontmatter(text)` = `yaml.load(text, CSafeLoader)`, and on ANY exception the same text through
  `yaml.safe_load` (so a refusal's sentence is the pure loader's). Used by `_read_fact` and the index's tags read.
- `component.py/.ts`: unchanged — the layered walk calls `store.recall`/`store.lookup` per layer, which now read
  through each store's own index. (Plan listed it; nothing there needed to change.)

**Runners**: `runtime-py/tests/conftest.py` autouse fixture sets `BANTAMKIT_INDEX_DIR` per node;
`runtime-ts/scripts/run-tests.mjs` sets it for the run; `tools/conformance/run.mjs` sets it to `<scratch>/hot-index`.

## Decisions on J69-2's open items
1. `query(terms)`: built (both runtimes), plus `query_words(words)`.
2. Duplicate names: recall today scores both files. Any `skipped` entry (incl. `duplicate name`) sends recall/lookup to
   the files, so the observable answer is unchanged. Same for an unreadable/malformed file (the `skipped` list's order
   and its retry-every-call behaviour stay the files'), and for a non-string name (`loose`: Python orders 9 before 10,
   and may raise across types). Cost: such a store is read at today's speed.
3. `avgdl` 9-dp rounding: recall never reads `avgdl` (v1 overlap score), so no recall answer can move; `--all` green.

## Deviations
1. A second shard family `words` (see above); head carries `loose` (files whose name is not a string) — not in the
   ruled head shape, needed to keep recall's answer exact.
2. `BANTAMKIT_INDEX_DIR` is new surface (both runtimes, conformance literal + mutation M9). Needed so no test or
   conformance run writes the operator's `~/.bantamkit/index`. Not yet in user docs (Task 8 / docs/storage.md).
3. Doc-shape checks are lazy (J69-2 checked every doc at load). The refresh literal gained one step (`set docs` →
   `fresh`, pinning that the fresh path reads no doc) and the `set version` step now writes 1 (the old layout) — the
   same property ("a version mismatch rebuilds") on the value that matters; 2 is now the current version.
4. Write-through never CREATES an index (a save into a store nobody has recalled leaves no index), and an absent
   `facts/` never gets one.
5. Python `snapshot()` reads keep the pinned list (no index).

## Open questions
1. Bar margins are thin (13.2 / 12.5 ms vs 15). The next lever is the head: `docs` carries every doc's
   links/tags/mtime/size (1.5 MB at 5,000) though recall reads only `file` for k hits.
2. A coarse-mtime filesystem (HFS+, FAT: 1-2 s) can hide a second write in the same tick from `refresh("fast")`;
   APFS/ext4/NTFS are fine. Not handled ("racily clean" in git's terms).
3. A store with any skipped file or loose name pays today's full read on every recall.
4. Off-topic, one line: Node accepts a quoted frontmatter value holding a raw BEL (`"\x07"`) that PyYAML refuses
   (`unacceptable character #x0007`) — a pre-existing parity gap, not touched.
