## Deviations from the plan
1. **`mtime_ns` is a decimal STRING on disk** (`dir_mtime_ns`, `files[f][0]`, `docs[n].mtime_ns`), not an integer.
   A real mtime is past 2**53 and `JSON.parse` rounds it; the exact decoder (`pyjson.parseJson`) took 42–61 ms on the
   5.5 MB index against `JSON.parse`'s 17 ms (`node -e` timing over the bench index), on the hook path. Property kept:
   exact, deterministic, byte-identical, either runtime reads the other's file.
2. Docs carry `str()`/`pyText()` of name/description/type (a YAML `name: 7` is `"7"`), which is what recall's
   `f"{name} {description}"` scores today.
3. A name held by two files: the file the store's listing reaches first wins (as `lookup` does); the other is
   `skipped` with `duplicate name '<n>': <file> holds it`, re-parsed whenever any other file moves. Not in the plan.
4. Native: Node has no port of `divergence.parse_fact`, so `hotindex.ts` ports it (same sentences) over the store codec,
   with the `metadata:` block cut out and read on its own, and indented block sequences moved to column 0.
   Native `links`/`tags` also come from under `metadata:` (Claude Code's own shape; see the real-data probe).
5. A loaded index whose `files`/`docs`/`skipped` entries have the wrong shape is rebuilt (one conformance step pins it).
6. "fast" with a moved directory answers `patched` even if no file changed (the plan's wording); "full" answers
   `patched` only if a file or the directory mtime moved, else `fresh`.
7. The spec's `query(terms)` is not built: Task 2's interface in the plan does not list it.
8. `docs/conformance.md` and `pyjson.ts` are not in Task 2's file list; the table gate requires the row, and the
   byte format required the two `dumpJson` options.

## Open questions
1. **The 1 s full-build bar is missed on Python (1.50 s; Node 0.34 s).** ~0.9 s is `yaml.safe_load` inside the store's
   own parser. Holding the bar needs either `yaml.CSafeLoader` in `MemoryStore._read_fact` (a store change, with its
   own parity risk on error text) or a cheaper tokenizer. Needs a ruling; not fixed here.
2. **Task 3's 15 ms recall bar at 5,000 facts looks unreachable with one JSON file:** loading the 5.5 MB synthetic
   index costs 42.9 ms (Python, `json.loads` alone ~33 ms) and 26.6 ms (Node). Real facts are bigger (205 KB / 75 =
   ~2.7 KB per fact -> ~14 MB at 5,000). Task 3 will need a split (e.g. postings apart from docs) or a smaller shape.
3. `avgdl` is stored through `pyRound9` per the plan; J68-5 scoring through `postings()` with it may differ from
   `bm25_scores` in the 9th decimal. Both runtimes agree either way.
4. Docs are keyed by name, so a duplicate-named file is not scored; recall today scores both. Task 3 should decide
   whether recall keeps that (it reads `skipped` for the reporting).
