## What changed (both runtimes)

- New `memory/native.py` / `memory/native.ts`: `NativeStore(dir)`, a read-only layer with the
  methods `Memory` calls on a layer (`pool`, `candidates`, `resolve`, `lookup`, `count`,
  `archived_recall` -> [], `snapshot` no-op). Reads `<dir>/*.md` except `MEMORY.md` through the
  existing native hot index (`HotIndex(dir, "native", ...)`, #204; index under
  `BANTAMKIT_INDEX_DIR` / `~/.bantamkit/index`, never in the dir) and `divergence.parse_fact` /
  `parseNative` (now exported from hotindex.ts). Description read as one line (#155 rule).
  Unparseable files and duplicate names go to `skipped` with the index's sentences; a missing or
  not-a-directory path is a silent layer of nothing (listing catches ENOENT/ENOTDIR).
- `store`: `Pool.every` (all names when rows are not every fact; `None`/`null` for an index pool),
  `Pool.all_names()` / `allNames(pool)`, and `pool_without(pool, drop)` / `poolWithout` (drop
  rows, renumber, re-run segments, recount df, subtract lengths from total). Node: `oneLine`
  exported, `MemoryStore.poolIndexed` made non-private (static).
- `component`: `Memory.layered(..., native=None)` / `MemoryOptions.native` appends
  `("native", NativeStore, writable=False)` LAST. `_pooled` collects every bantamkit pool's names
  (`shadow`) and the native pool drops them BEFORE scoring (property 4); repool does the same.
  Counts use the native listing (`_count` / `countOf`, `_layer_count` / `layerCount`);
  `_fact_count(root)` keeps its signature (status.py/status.ts call it). `_repair` only ever sees
  writable layers, so native is never repaired; `_use` records `recall_hit`/`body_read` by name in
  the project ledger like any other hit. `layered_for_eval(..., native=None)` / `layeredForEval(...,
  native)`.
- Hook (`_user_prompt_submit` / `userPromptSubmit`): `native = _resolve_native_memory(run, payload)`
  (all three branches) -> `Memory.layered(cwd, native=native.dir)`. Still `stamp=False`: writes
  nothing.
- MCP server (`mcpserver._build_memory` / `cli.ts buildMemory`):
  `native=native_memory_dir(home)` (branches 1-2 only). `--store` gets no native layer.
- `tools/eval/recall/score.py --native <copy dir>` (v2 only).
- `docs/memory.md`: Layers table row + "The `[native]` layer" section.

## Deviations / limits (stated, property kept)

1. Not in the plan text (the plan has no J68-11 task); the brief's six properties are the spec.
2. The real machine: `~/.claude/settings.json` has no `autoMemoryDirectory` and the env override is
   unset, so `memory_recall` over MCP gets NO native layer here today; only the hook (branch 3 via
   `transcript_path`) reads it. That is RULING Q1.2 as the brief states it.
3. The real bantamkit auto-memory dir holds one file without frontmatter
   (`project-bantamkit-program-backlog.md`): with the layer on, every hook recall logs it in
   `skipped` and every tool reply ends with the "1 fact file could not be read" note for
   `[native]` — property 3 ("same skipped reporting"), but visible noise for the user.
4. The MCP `instructions` "Layers" paragraph (assets) still names `[project]`, `[extra:<name>]`,
   `[profile]` only; not edited (contract golden + instruction-drift gates; Task 8 docs unit).
5. `status` (`unreadableLayerCondition`, Python twin) still counts layers with
   `_fact_count(store.root)`: for the native layer that is `<dir>/facts`, so 0 — the status line
   never calls a native dir unreadable. Recall itself does (`_layer_count`).
6. In-layer tie order: within native, the second file claiming a name is skipped (index rule),
   unlike bantamkit stores (both scored) — mirrors the native hot index.
