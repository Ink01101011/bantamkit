## pyRound9 (round-half-even)
`grep -rn "half.even\|pyRound\|roundHalfEven" runtime-ts/src` finds only `formatFixed3` in `memory/dream.ts:339`. That is a string formatter at 3 places, not `round(x, n)`, so nothing could be reused. `roundHalfEven` ports CPython's `double_round`:
1. Take the correctly rounded decimal: dtoa mode 3, half-even on the EXACT binary value. Here that is done with BigInt, using `mantissa * 2**exponent`, the same decomposition as `formatFixed3`.
2. Parse it back with `Number()`.
3. Keep the sign, so `round(-1e-12, 9)` is `-0.0`.

Non-finite values are returned unchanged, and so are integer-valued doubles (exponent >= 0).

DEVIATION: the plan sketched `Math.round(x*1e9)/1e9` with a `toPrecision(17)` tie fix, behind a `toFixed` shortcut. I did not use it, because it rounds twice. Mutation M8 below is that naive form, and it is red on 3 of the 5 groups. The plan's property, Python's `round(x, 9)` exactly, pinned over 1,000 seeded doubles, is held.

Ties in the seeded set are real ones:

    cd runtime-ts && node --input-type=module -e "import * as r from './dist/memory/retrieval.js'; let n=0; for(let j=1;j<40000;j+=2){const x=j/1024; if(Number(x.toFixed(9))!==r.pyRound9(x)) n++} console.log(n)"   # 10000 (of 20000 odd j)

Seed: splitmix64(0x199). The five groups, 200 doubles each, are:
- uniform [0, 30);
- exact ties j/1024, signed;
- near ties (m+0.5)/1e9;
- random finite bit patterns;
- small signed [-1e-8, 1e-8).

Values travel as 16-hex-digit bits, so -0.0 and the last ulp are compared exactly.

## Deviations from the plan
1. `pyRound9` uses an exact BigInt port, not the `Math.round` + `toPrecision` sketch. See above.
2. `docs/conformance.md` is not in Task 2's file list. Its `recall-retrieval` row said BM25F "joins in later units", which would have been false after this commit, so I updated the row text. No new row was added and the heading count is unchanged.
3. The `round9` op sends doubles as hex bits rather than JSON floats. The property is the same, and -0.0 survives the trip.
4. The ref op `bm25` takes `queries: [...]` (a batch) rather than one `query`. The property is the same, with fewer subprocesses.
5. The plan's "M5: Python drops the keywords field" is implemented as removing `keywords` from `FIELD_BOOST`.
