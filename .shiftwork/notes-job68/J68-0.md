## Deviations from the plan (property kept, code followed)
1. **Memory file regex** — plan's `/memory/([a-z0-9-]+)\.md$` misses bantamkit store reads
   (`.../memory/facts/<name>.md`). Now `[/\\]memory[/\\](?:facts[/\\])?<name>\.md$`.
2. **Meta / sidechain / subagents** — records with `isMeta` or `isSidechain` are ignored
   (neither open nor close a prompt window), and `subagents/` transcripts are skipped:
   those are hand-backs, hook text and subagent briefs, never a prompt the
   UserPromptSubmit hook sees. `[Request interrupted…` is not a prompt either.
3. **v1 shim** — plan used `os.environ["BANTAMKIT_MEMORY_DIR"]=profile_root` +
   `Memory.layered(start=store_root)`. Against the code that is wrong: that env var is the
   PROJECT pin (`layers._pinned_store`), and `layered` reads the profile from
   `Path.home()` and grants beside the project store — i.e. live data. `score._v1` builds
   `Memory(store_root)` + a `("profile", MemoryStore(profile_root, create=False))` layer by
   hand: the layer list `layered` builds for a session with no grants. `RecallOutcome` has
   no `hits`; names are parsed from `headers` (`[layer] [name] (type) desc`, #155).
4. **build_gold.py** needs `--store-root/--profile-root` (for v1 top hits and the random
   pool); "stratified" = by session (one row per session per round). Prompts deduplicated
   by text; candidates shuffled so position does not leak provenance. Seed 199.
5. `score.py` accepts `--set {silver,gold}` (recorded only).
6. Label space (`--known`): the profile and project store copies PLUS every non-empty
   `~/.claude/projects/*/memory` auto-memory dir (10 dirs), copied under `stores/automem/`.

## Open questions (for the orchestrator / user)
1. **Label space vs. engine reach**: 53/70 silver rows are positive only on auto-memory
   facts that no bantamkit store holds, so v1 and (unless Task 5 pools auto-memory) v2
   cannot score them. Silver tuning in Task 7 should probably use the in-store subset
   (`silver-instore.jsonl`, 17 rows) or the engine must read auto-memory. Decide before J68-7.
2. **Gold skews Thai**: 48/50 gold candidates are Thai because silver is 67/70 Thai; only 3
   non-Thai silver prompts exist. The `--thai-min 20` floor is met many times over.
3. 37 of 50 gold rows have NO in-store silver positive (the silver positive
   is auto-memory only); the user's ✓ on those still measures something v1/v2 cannot reach.
4. Silver is small (70 rows); label only fires on an exact-name `memory_recall` or a Read
   of a memory file, so word-search recalls contribute no labels.
