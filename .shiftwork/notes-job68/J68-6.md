## What changed (both runtimes)

- `Fact.extra` (Py `dict`, Node ordered `[key, value][]`, absent when empty): every frontmatter key
  outside `OWNED_KEYS` (name, description, type, created, last_recalled, links, keywords), in file
  order. The formatter (`_fact_text` / `formatFact`, and `factOfParsed`) re-emits them after the
  owned keys. `save` of an existing name carries `existing.extra`. A key PyYAML does not read as a
  `str` (`on:`, `true:`, `null:`) is carried by NEITHER side (Py `isinstance(k, str)`, Node
  `typeof constructPlain(k) === 'string'`): the port reads every key as text and could not spell
  it back the same way. YAML comments are lost (safe_load), as the plan says.
- `MemoryStore.repair(fact, ledger, now) -> bool`. Old = non-null `last_recalled`, or empty
  `keywords` while `ledger.keywords_copy(name)` is non-empty. Writes through `_write_fact`/`writeFact`
  (one temp+rename) with `last_recalled: null` (line kept), keywords restored, extras kept; then
  `_after_write`; THEN appends one `seed` event at `usage.seed_ts(str(stamp), now)`.
  Node's `ledger` param is a structural `RepairLedger` so the `.d.ts` names no `UsageLedger` (#144).
- `usage.seed_ts`/`seedTs`: the stamp's leading `YYYY-MM-DD` at `T00:00:00Z`; `None` if not a real
  calendar day; clamped to `now` if later. `UsageLedger.census()` -> (lines, skipped).
- `Memory`: `repaired` counter; `_repair(picked)` on the TOOL path only (`stamp=True`), only for
  hits in a writable layer, both the pooled walk and the exact-name walk; never raises (#123).
  `save_outcome` appends a `save` event carrying `keywords` (always, `[]` when none, so a re-save
  that drops keywords supersedes the old copy). `usage_census()`/`usageCensus()`.
- `bantamkit_status`: two lines after the storage block — `read-repaired: <n> this process`,
  `usage ledger: <path> (<lines> lines, <skipped> skipped)`.
- `dream` (J68-3 amendment): survivor `keywords` = project's in order + each profile keyword not
  already present (exact compare); `extra` = project's, plus profile keys the project lacks.

## Deviations from the plan (property kept)

1. Order inside repair: WRITE first, then seed. Plan lists seed first. Reason: a write that fails
   (unwritable store) would otherwise seed again on every recall and inflate usage; this way a
   failed write seeds nothing and the next use retries. If the seed append fails after the write,
   the stamp's day is lost (the ledger is best-effort, #123).
2. `now` is used to clamp a future stamp (a hand-edited `2099-01-01` would otherwise sit at age 0
   until 2099). The conformance fixture uses a stamp before the frozen TODAY for that reason.
3. Status lines are placed AFTER the storage block (not inside the `memory:` line area), so every
   pinned line 0..9 keeps its number (the J69-7 precedent). Existing pins amended where the plan
   names the change: `len(lines)` 10 -> 12 (py, 2 nodes), Node server.test rows +2 for problem
   blocks; `logs:` literals that pinned the ledger WITHOUT a save event (storage-tiers 70 -> 148
   bytes; store.mjs D5 ledger literal gains the `save` line; Node `statusSession` gets its own HOME
   because saves in sibling tests now leave ledgers in the shared `fakehome`). Every amendment
   cites "plan Task 6" in a comment.
4. Repair refuses (returns False) a fact whose file is not `facts/<name>.md`, or whose name is not
   NAME_RE-valid: `_write_fact` would otherwise write a second file beside it.
