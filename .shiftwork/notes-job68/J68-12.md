### `version` suite

Three fixture trees built per run under the harness scratch: a copy of `runtime-py/src/bantamkit`
with `__version__` patched, plus a copy of `runtime-ts/dist` with a patched `package.json` beside it
(dist COPIED, because ESM resolves `import.meta.url` through symlinks). Both servers run as processes
under a throwaway HOME, in lock-step: initialize, then `build_identity`. When stdin closes before
the server answers `tools/call`, the reply is `Connection closed`. I measured that while prototyping.

Fixtures are `0.36.0`/`0.36.0`, `0.37.0b1`/`0.37.0-beta.1` and `0.37.0rc2`/`0.37.0-rc.2`. Both
surfaces are checked: serverInfo.version and build_identity version.
- **stable:** compared byte for byte (non-ruled).
- **prerelease:** a `ruling:` case (the spellings DIFFER) and, beside it, a non-ruled case that
  compares `pep440ToSemver(reference)` with the port's answer.
- **every fixture:** a per-side literal for each spelling.
- **once:** `pep440ToSemver` against publish.sh's `map_pep440_to_semver` over 15 spellings.

23 cases, 4 ruled.

Rerun: `TMPDIR=<scratch>/cleantmp/ node tools/conformance/run.mjs --suite version`

## porting.md row (verbatim)

| a prerelease version's spelling (job68 J68-12) | **one version, two registry spellings, and each runtime reports its own registry's.** PyPI requires PEP 440 and npm requires semver, so a prerelease cannot be one string on both: `runtime-py/src/bantamkit/__init__.py` declares `0.37.0b1` and `runtime-ts/package.json` declares `0.37.0-beta.1`. Each runtime reports the spelling of the registry it was published to — in `serverInfo.version` and in `build_identity`'s `version` — because a client that compares that number with its own registry (`pip index versions`, `npm view`) must find it there. Rewriting either side to the other's spelling would make one runtime report a version its own registry cannot carry. The two are ONE version after `tools/release/publish.sh`'s `map_pep440_to_semver` (`aN` → `-alpha.N`, `bN` → `-beta.N`, `rcN` → `-rc.N`), and a STABLE version is still byte-identical. User ruling 2026-10-15. Gated by `tools/conformance/suites/version.mjs` over fixture trees (no manifest is bumped): the prerelease `ruling:` cases pin that the two spellings DIFFER, a non-ruled case beside each pins that the reference's answer mapped through `publish.sh`'s mapping is byte-identical to the port's, per-side literals pin each spelling, a stable `0.36.0` is compared byte for byte, and `pep440ToSemver` is checked against the script's own function. `test_version_agreement.py` and `packaging.test.mjs`'s `the two version declarations agree` compare the declarations the same way, `wire`'s `build_identity: version agrees` and `cli`'s four `…/handshake` frame comparisons map the reference's `version` before comparing, and `server.test.mjs`'s status-report line compares against `package.json`'s own version instead of a stable-only `\d+\.\d+\.\d+` shape. |

## The beta bump, end to end, on a throwaway copy

Setup: rsync the tree to `<scratch>/beta/tree`, excluding `.venv` and `runtime-ts/node_modules`, then
symlink node_modules back in. Set `__init__.py` to `0.37.0b1`. Set `package.json` and both lock
fields to `0.37.0-beta.1`. Set the README pin to `0.37.0b1`. Run `npm run build`. Use
`BANTAMKIT_CONFORMANCE_PYTHON=<repo>/.venv/bin/python` and `PYTHONPATH=<copy>/runtime-py/src`.

The first beta run, which had the version-agreement tests and wire `build_identity` already mapped,
found more beta-red spots that the brief did not name. All of them are fixed here:
- `cli` --suite: 4 failed (the four `…/handshake` frame comparisons, at `serverInfo.version`).

  `status-active` / `status-degraded` / `eventlog-never-creates-the-store` / `index-band` id 3/4/14/16
  plus their raw bytes, where the status report's `version 0.37.0b1, build …` line differs.
- npm: 1 failed (`a healthy server reports Active…`, the stable-only regex).
- pytest: `test_conformance_suite_table_gate` (the new suite moved the count to 26).
