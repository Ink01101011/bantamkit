## Perf continuation (2026-10-16) — the 5,000-fact bar

### What changed (both runtimes; layout still head + 16 term-hash postings shards, spec S3)
- `hotindex.py/.ts` INDEX_VERSION 4. The head is ONE JSON object written in TWO lines
  (`head_text`/`headText`): line one = stamps, shard prints, `skipped`, `loose`, `avgdl`,
  `lens_total`, `boost`, and `cols` (per doc in name order: name, file (`""` = `<name>.md`),
  length = Σ boost·count, type code into `cols.types`, stale ids); line two = `files`, `docs`,
  `df`, `lens`, parsed lazily (`_complete`/`completeTail`) only by a patch or a full read. A head
  in any other layout (one line: a hand edit, the conformance `set` op) is parsed whole and
  checked whole, exactly as before. `boost` mismatch = missing index.
- Postings shards: per term a flat run-length list `[start, count, tf_name, tf_desc, tf_kw, ...]`
  over integer doc ids. `query()`/`postings()` decode to the old `[name, field, tf]` rows (API and
  every existing assertion unchanged); `segments()` is the raw form for the scorer.
- `retrieval.py/.ts`: `bm25_segments` (same doubles in the same order as `bm25_postings`; one
  division per distinct norm per run, added a slice at a time in Python), `weight_of`,
  `rank_columns` (= `rank` when ids run in (layer, name) order; stable reverse sort).
- `store.py/.ts`: `Pool` is columnar (names, lengths, type codes, stale ids, run-length segs;
  `facts` on the files path, `files` on the index path). `pool_of` sorts its rows by name (stable)
  so a row id is the tie-break. `pooled_ranking` lays layers end to end, scores once, ranks, and
  spells `(layer, row)` lazily; only hits are parsed (`resolve(pool, row)`). `_pool_indexed`
  reads only line one + the shards q hashes to. `_indexed_fact` uses `file_of` (line one).
- Name→id cache keyed on the names column, not the head object (a patch mutates the head in
  place) — found by storage-index: Node `lookup` after `save` missed.
- Tests changed on purpose (encoding ruling, brief: "the encoding is yours, index version bump
  allowed"): `test_bytes_are_the_deterministic_dump` / TS `bytes are the deterministic dump` now
  compare against `head_text(data)` (WAS `dumps(data)`), every other assertion kept.
- Docs: docs/storage.md (hot index paragraph), docs/conformance.md (storage-index and
  recall-retrieval rows).
- No answer moved: old tree (HEAD + `$SP/J68-5-uncommitted.patch`, extracted to `$SP/old`) vs new,
  300 random stores (duplicates, int names, Thai, stale openings, odd types, usage ledgers, two
