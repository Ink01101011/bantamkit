## 2. What changed

- **#119** — `MemoryStore.facts()` throws on the first file it cannot parse; the store is
  J65-6's layer and was NOT edited. The hook now has `tolerantFacts` / `_tolerant_facts`: only
  after the whole-store parse failed, it asks the store's OWN parser one file at a time by
  narrowing `factPaths` / `_fact_paths` (the single listing `facts()` walks, on both runtimes)
  on the hook's own store instance, keeps every fact that parses, and leaves the instance
  narrowed so later reads skip the same files. No second parser. Used by SessionStart's
  `cappedIndex` (profile and project), the native export, and UserPromptSubmit (via
  `quarantineLayers` over `Memory.layered`'s layers, then one more `recallOutcome`, only when
  the first recall threw or counted a layer `unreadable`). The profile block is in its own
  try (a store that cannot be listed costs that block only). Reporting: a block footer
  `[N fact file(s) not read — not a valid fact: a.md, b.md; ~/.bantamkit/hooks/hook-log.jsonl has the reason]`,
  log fields `profileSkipped` / `projectSkipped` / `nativeUnparsed` / `skipped` (`{[layer,] file, reason}`),
  each present only when non-empty. Healthy path cost: unchanged (one parse / one recall).
- **#188** — header noun follows the block's total: `1 fact`, `N facts` (`15 of 20 facts`).
- **#168** — parse-error record is `{event, bytes, sha256}` of the UTF-8 input; no `raw`.
- **#169** — the native-write half is now a parse of transcript lines prefiltered on
  `"name":"Write|Edit|MultiEdit"`: a `tool_use` of those tools whose `file_path` is a `.md`
  under `memory/`. The `memory_save` name match is unchanged (it was not the defect, and the
  existing `test_a_session_that_saved_a_memory_is_not_nudged` pins it with a synthetic line).
- **#192** — CHOICE: an `R_OK` check (`fs.accessSync` / `os.access`) on PreToolUse after the
  regular-file check; a failing file is treated like a missing path (not ledgered, never
  refused, no log line). Chosen over moving the record to PostToolUse[Read] success: one check
  in the arm that already decides, no second event/registration. Written into docs/hooks.md
  (PreToolUse row), with the uncovered case (file deleted between hook and Read).

   tool) must still return `prof-ok`; `Memory.recallOutcome` (`runtime-*/memory/component.*`)

   files. The clean fix is a tolerant listing in the store (`facts()` that skips and reports),
   which would also let the hook drop its `factPaths` narrowing. #119 therefore left OPEN.
2. The hook reaches a private member (`factPaths` / `_fact_paths`, and `Memory.layers` /
   `_layers`) by instance override. Sound today (facts() is the only caller of factPaths on
   both sides) but it is a seam the store does not declare; see 1.
3. J65-4's open question 1 (UPS/PostToolUse/Stop ledger writes are unlocked) is untouched:
   this unit's Stop/UPS edits did not change their ledger writes.
