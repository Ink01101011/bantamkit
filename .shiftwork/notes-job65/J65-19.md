## 2. What changed, both runtimes

**Design: both runtimes ask their own package manager, install exactly what it answered, and
read the install back.** One shape on both sides; the sentences stay byte-identical; the
commands stay the ruled difference.

- `runtime-ts/src/selfupdate.ts`, `runtime-py/src/bantamkit/selfupdate.py`
  - #135: `INDEX_URL` is gone. `indexCommand(environment)` = `npm view --prefix <root>|--global
    bantamkit-mcp@latest --json --fetch-retries=0`; `index_command()` = `<sys.executable> -m pip
    install --dry-run --no-deps --ignore-installed --retries 0 --disable-pip-version-check -q
    --report - bantamkit`. `fetchIndex(command, timeout)` / `fetch_index(command, timeout)` spawn
    it with the deadline as the spawn timeout (`ETIMEDOUT` / `TimeoutExpired` → the timeout
    refusal); a non-zero exit is `UNREACHABLE` with npm's JSON `error.summary`/`code` (then first
    stderr line, then `exit N`) or pip's last `ERROR:` line (then last line, then `exit N`). The
    `--prefix`/`--global` on the view mirrors the install so both read the same project
    `.npmrc`. The Python JSON path moved from `info.version` to `install[0].metadata.version`.
    No `urllib` is left in the module.
  - #128: `upgradeCommand(environment, latest)` → `bantamkit-mcp@<latest>` (`--save-exact` when
    the prefix manifest pins exactly — `Environment.exact`, read by `installEnvironment`);
    `upgrade_command(latest)` → `bantamkit==<latest>`. After exit 0 a third seam,
    `installedVersion(environment)` (default: the tree's `node_modules/bantamkit-mcp/package.json`)
    / `installed_version()` (default: `importlib.metadata.version("bantamkit")`, read afresh), is
    compared with `compareVersions`; a mismatch or nothing readable raises the new byte-identical
    `NOT_INSTALLED` (`the update command exited 0 but did not install {latest}: {command}` /
    `{program} now reports {found}, not {latest}; the tree the command names did not take the
    update.` / `{printed}` / `{output}`), with `NO_INSTALLED_VERSION = "no readable version"`.
  - #177: `NO_ROUTE` and `NO_RECORDED_ROUTE` take `{article}` (`article()` / `_article()`, a
    letter test); `NO_RECORDED_ROUTE` is now a named constant on Python too. Node's `runUpdate`
    names `packageRoot(packageDirectory)` — the nearest `package.json` above `dist/` — for a
    checkout. `cli.ts` and `mcpserver.py` are untouched (not this unit's files; the defaults do
    the work).
- `runtime-ts/src/npminstall.ts`: `spawnCommand(command, timeoutMs?)` factored out of
  `runInstaller` (same Windows shim rule); `runInstaller`'s signature and behaviour unchanged, so
  J65-18's `hostinstall.ts` is unaffected.
- Tests: `runtime-ts/test/selfupdate.test.mjs` (68 tests), `runtime-py/tests/test_selfupdate.py`
  (64). New: the verify arms (old version / nothing readable / padded `0.30`), the article on
  every shape and an unknown vowel-initial one, `packageRoot`, `--save-exact` only on an exact
  pin, the subprocess failure mapping (sleep → timeout; JSON summary / `ERROR:` line / silent exit
  / missing program), the dist-info re-read under a running process, and **the real package
  managers against loopback indexes**: npm with `npm_config_registry` at a child-process registry
  (a server on the test's own loop cannot answer a `spawnSync` child — measured as
  `spawnSync npm ETIMEDOUT`), pip with `PIP_INDEX_URL` at a simple index of two tiny wheels and
  `PIP_CONFIG_FILE=/dev/null`. The Python no-network gate's complement now requires
  `subprocess` in `fetch_index` and forbids `urllib`/`http`/`socket` anywhere in the module
  (the old complement required `urllib.request`; #135 changes the mechanism, the gate's purpose
  — one function reaches the network — is kept).
- `tools/conformance/ref/update_ref.py`, `tools/conformance/suites/cli.mjs`: the seams take
  `(command, timeout)` and an `after` per arm (`landed`, default = the compared version, trimmed);
  three new in-process arms (`behind-but-the-tree-kept-the-old-version`,
  `behind-but-nothing-readable-afterwards`, `behind-and-the-tree-reports-it-padded`), one new
  garbage arm (`garbage-the-old-pypi-path`), one new dispatch arm (`behind-but-not-installed`);
  per-side pins for the index COMMAND and document shape, the versioned upgrade commands plus
  the `--save-exact` fork, the `NOT_INSTALLED` refusal, and the article; and **two real-process
  specs**, `update-registry` and `update-registry-lying-installer`: both CLIs run from a
  registry-shaped copy of this build with the package manager stubbed where each resolves it
  (`npm` shell script first on the port's PATH, self-probed like `npmStub`; a `pip` package first
  on the reference's PYTHONPATH beside a site copy of `bantamkit` with a dist-info whose RECORD
  owns the running file). The stubs record argv; the cases pin per side what was asked and the
  exact spec installed, read the tree's version back, rule the command line, and compare every
  other byte of both streams.
- `docs/porting.md` (two local hunks: the AS-7b command row, and a J65-19 paragraph after the
  URL paragraph), `docs/install.md` (a paragraph in *Updating*). `docs/release-npm.md`: nothing
  in it names the version check; unchanged.

## 7. Open questions / for the reviewer

1. `tools/hooks/update-probe.mjs` still fetches `registry.npmjs.org` and `pypi.org` by URL for
   the stale-install record — the same #135 shape, out of this unit's files. Not fixed.
2. `README.md` / `runtime-ts/README.md` update rows still spell `bantamkit-mcp@latest` for the
   kept-install command (not this unit's files); `docs/install.md` names the change.
3. The `UNREACHABLE` reason is now npm's or pip's own sentence (`request to http://… failed,
   reason: connect ECONNREFUSED`, `No matching distribution found for bantamkit`), so a mirror
   that is DOWN reads on Python as "no matching distribution" — pip's words, kept rather than
   paraphrased. `--retries 0` on pip and `--fetch-retries=0` on npm mean one attempt.
4. The `update_ref.py`/`cli.mjs` docstring claim "there is no env var that redirects the lookup"
   was true by design and is now false by design (the package manager's own config does); the
   docstrings and `docs/porting.md` say so. If the user wants the old "never redirectable"
   property back, #135 cannot be closed.
5. `pip index versions --json` would be a cheaper question than `--dry-run --report -` once the
   bundled pip carries it (not in 25.0.1); the report route costs one wheel/metadata fetch.
