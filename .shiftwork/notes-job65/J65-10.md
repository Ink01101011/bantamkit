## #158 — what changed

- layers.py: a `ScannerError` whose `problem` is exactly `found character '\t' that cannot start
  any token` becomes `invalid memory config <cfg>: line L, column C: a tab cannot start a YAML
  token; indent with spaces` (L/C from `problem_mark`, 1-based). Any other YAML error keeps its text.
- layers.ts: `firstTokenTab(text)` finds the first such tab before the reader runs and throws the
  same sentence (`tabSentence`). It is a small scanner (quote, flow depth, plain-scalar state,
  comment at a token start, multi-line plain continuation by indent), built off PyYAML's measured
  behaviour:

      .venv/bin/python - <<'EOF'   # the battery: every tab outside quotes/comments is refused
      import yaml
      for t in ['extra_stores:\n\t- a\n','key:\tv\n','extra_stores:\n  -\ta\n','k: v\t# c\n',
                'k: [a,\tb]\n',"k: 'a\tb'\n",'# a\tb\nk: v\n','---\t\nk: v\n']:
          try: print(repr(t), yaml.safe_load(t))
          except yaml.YAMLError as e: print(repr(t), e.problem, e.problem_mark.line+1, e.problem_mark.column+1)
      EOF

- Agreement measured, rerunnable:

      .venv/bin/python .shiftwork/notes-job65/J65-10-probes/fuzz.py 1 50000 | node .shiftwork/notes-job65/J65-10-probes/fuzz.mjs
      # {"n":50000,"agree":46671,"tabMismatch":41,"falseRefuse":0,"otherButTab":3288}
      mkdir -p $TMPDIR/j6510b; .venv/bin/python .shiftwork/notes-job65/J65-10-probes/real.py 3 4000 $TMPDIR/j6510b | node .shiftwork/notes-job65/J65-10-probes/real.mjs
      # 12000 config-shaped docs over seeds 1-3: 0 verdict differences CAUSED by a tab

  `falseRefuse` (Node refuses a tab PyYAML accepts) is 0 over 150000 random documents.
  `tabMismatch` (PyYAML names a tab, the scanner does not) are pathological root-scalar documents
  (a root plain scalar continuing at column 0); the Node reader refuses those anyway, in its own
  words. Where a document holds an EARLIER non-tab error, PyYAML reports that one and Node names
  the tab: both refuse, different words (the existing reader ruling covers it; documented).
- docs/memory.md (Grants) carries the rule.

## #154 — what changed

- `EventLog` (both) gains `requires_dir`/`requiresDir`; `from_env`/`fromEnv` sets it to the store
  root iff the switch is `on`/`1`/`true`/`yes`. `_append`/`append` returns before any I/O when
  that directory is not there: the record is DROPPED, not redirected, `write_failed` stays false

  save's record and every later one land. A literal path still creates its parents.

- The J51-1 gitignore tests construct `EventLog(default_path(root))` directly (literal path), so
  they are untouched and still green.
