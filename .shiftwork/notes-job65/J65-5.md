## 2. What changed (both runtimes, statement for statement)

**#117 — reserved ledger keys are refused.** `RESERVED_LEDGER_KEYS = ("unit", "role", "status",
"ts", "event")` on both sides, same order. `_reserved_refusal` / `reservedRefusal` runs AFTER the
F5 shape check (whose `additionalProperties: true` lets these keys through) and before any
mutation, like the roles and shape gates: nothing written, checkpoint byte-unchanged. One sentence,
the keys named in the runtime's order whatever order the caller used:

    unit A in role implementer reported an accounting line that sets the runtime's own keys: unit, status, ts, event

A refusal rather than a merge-under, because a line whose keys were silently dropped is a line the
orchestrator believes it wrote. `briefed` is deliberately NOT in the five: F6 ruled a self-reported
`briefed` is OVERWRITTEN by the measured value, that is pinned on both sides and in the docs
(`briefed/self-report-*` sessions, `test_briefed_is_measured_by_the_runtime_...`), and #117's own
Expected lists exactly these five. The issue's three-step repro (§1) now answers refused / refused
(this sentence) / refused (`unit C is not the cursor unit A`), statuses `A=todo B=todo C=todo`.

**#162 — a failed commit no longer spends the brief.** Log-then-commit is KEPT (the accounting is
never lost; the sentence `checkpoint unwritable, last log line uncommitted: …` is unchanged and
still true). In that one failure arm `clock_out` now appends a marker line right after the orphan
accounting line, best effort, through the same helper the brief line uses:

    {"event": "uncommitted", "role": "implementer", "ts": "...", "unit": "B"}

and `_briefed` / `briefed` learn one rule: an `uncommitted` line restores the flag to whatever it
was before the accounting line it follows. So brief → clock-out(uncommitted) → retry reads `true`
and the retry of a briefed NON-cursor unit is accepted (before: `unit B is not the cursor unit A`);
the F6 ruling is kept for the shape it was written for — brief → clock-out(blocked) → inline
re-run still reads `false` — because the marker is what now tells the two apart. A reader that
skips event lines (`event` present, `status` absent) skips the marker too. Chosen over
commit-then-log (which would make "never lose the accounting" false and the `uncommitted` sentence
a lie) and over rewriting the orphan line in place (the ledger is append-only and `clock_in` writes
it without the lock).

**#164 — `clock_in()` applies the readiness test.** The default path and the named path are one
path: `selected = cursor if unit_id is None else unit_id`; the dangling-cursor `escalate` stays
above the graph with its sentence; then the batch view (a refusal passes through verbatim on both
paths); then `selected not in ready` → `unit A is not ready; ready is B`. A done/dropped cursor
unit is not in `ready` (the batch view drops terminal units), so it meets the same sentence as a
unit whose dependency has not run — one property, one sentence, as D1 ruled. The old docstring
sentence "`unit_id` omitted is the whole prior contract, byte for byte" is rewritten on both
sides. `clock_out` on a graph that cannot batch still RECORDS (unchanged).

Docs: `docs/shiftwork.md` workflow steps 2 and 4, the failure-modes table (+3 rows), *Clock-in
writes too* (the marker and the rule), *What an accounting line means* (the five reserved keys,
`briefed` excluded), *Spending the width* (the default path, the graph refusal on both paths, the
dangling cursor still above both). Both module header docstrings.
