## 2. What changed (both runtimes, one protocol)

`runtime-py/src/bantamkit/shiftwork.py` and `runtime-ts/src/shiftwork.ts`, statement for statement:

- **#116 lock.** `clock_out` takes `<real>.lock` with `O_CREAT|O_EXCL` (Python `os.open`, Node
  `openSync(.., 'wx')`) around the WHOLE read-modify-write, releases it in `finally`. The same
  primitive as `driver.lock` and the hook ledger's lock J65-4 landed (#167), so a Python writer
  and a Node writer serialise against each other on the one checkpoint they share. Constants
  `LOCK_WAIT_MS = 5000`, `LOCK_STALE_MS = 30_000`, `LOCK_POLL_MS = 5` on both sides. Policy: a lock
  that exists is waited on; one older than `LOCK_STALE_MS` (mtime) is a dead holder's and is
  removed; past `LOCK_WAIT_MS` the clock-out answers
  `{"result":"error","reason":"checkpoint locked by another clock-out, nothing written: <lock>"}` —
  never let through unlocked (the ledger's policy is the opposite, deliberately: a hook that fails
  the tool call is worse than a lost cache entry; a checkpoint let through is the race itself).
  The lock is taken BEFORE the read and before the log line, so a lock refusal leaves no orphan
  accounting line. One arm goes on unlocked: the directory refuses to hold a lock for a reason
  other than EEXIST (read-only, gone) — the temp file cannot be created there either and ITS
  refusal names the cause, so `readonly-directory-before/after-the-log-line` keep their arms and
  their sentences.
- **#116 temp name.** `<real>.<pid>.<8 hex>.tmp`, created exclusively (`Path.open("x")` /
  `flag: 'wx'`), never `with_suffix(path.suffix + ".tmp")`. A suffix-less `checkpoint` no longer
  touches `checkpoint.tmp`. The write-failure sentence `checkpoint unwritable, last log line
  uncommitted: [Errno N] ...: '<path>'` now carries the checkpoint AS GIVEN in the filename slot
  (Python `OSError(e.errno, e.strerror, str(path))`, Node `new PyOSError(..., path, null,
  e.winerror)`), because a random temp name in a sentence is not reproducible across runtimes or
  runs. The two `readonly-directory-*` conformance sessions changed answer accordingly
  (`.../checkpoint.json'` instead of `.../checkpoint.json.tmp'`); both sides moved together.
- **#137 realpath.** `real = path.resolve()` / `pyResolve(path)` (falling back to the path on a
  symlink loop) is the rename target, the lock's and the temp's base. The READ, the ledger
  (`<given>.log.jsonl`) and every sentence still use the path as given, so no `log` field or
  errno sentence moved for a non-symlinked path. The link stays a link; its target carries the
  clock-out; `status` through either path sees the new cursor.
- **#163.** `_read_valid` / `readValid` catch `UnicodeDecodeError` / `PyUnicodeDecodeError` beside
  `OSError` and answer `checkpoint unreadable: 'utf-8' codec can't decode byte 0xff in position 1:
  invalid start byte` — the missing-file control's own sentence head — on all four entry points.
  Invalid JSON already answered `checkpoint is not parseable as JSON: ...` (structured, never
  raised; pinned by existing tests on both sides), so that sentence was NOT renamed: the brief's
  (c) is met on the "never raised" axis and the UTF-8 arm takes the `unreadable` head.
- **#165.** After schema validation, `_read_valid` / `readValid` refuse a repeated unit id with
  `workplan`'s own sentence `duplicate node id <id>`, so status/clock_in/clock_in(unit_id)/
  clock_out answer byte for byte what `shiftwork_plan` already answered through the core, and the
  plan view's answer did not move.

### `race.mjs`

```
// J65-1 race probe: two writers clock out DIFFERENT units of one checkpoint at one instant.
// usage: node race.mjs <repo> <py|node> <py|node> [trials]
import fs from 'node:fs'; import os from 'node:os'; import path from 'node:path'; import { spawn } from 'node:child_process';
const [repo, w1, w2, trialsArg] = process.argv.slice(2); const trials = Number(trialsArg ?? 10);
const PY = path.join(repo, '.venv/bin/python'), DIST = path.join(repo, 'runtime-ts/dist');
const W = fs.mkdtempSync(path.join(os.tmpdir(), 'bk-race-')); process.env.HOME = path.join(W, 'home'); process.env.USERPROFILE = process.env.HOME; fs.mkdirSync(process.env.HOME);
const unit = (id) => ({ id, title: id, brief_path: 'b.md', status: 'todo', role: 'implementer', depends_on: [], verify: 'true' });
const checkpoint = (units, cursor = units[0].id) => ({ version: 1, job: { id: 'j', goal: 'g', done_definition: 'd', constraints: [] }, plan: { cursor, units }, state: { repo: { branch: 'b', head_sha: 'h', dirty: false }, artifacts: [], external: [] }, history: [], retro: [], handoff: { next_action: 'n', open_questions: [], do_not: [] } });
const pySnippet = `import sys,json,time\nfrom bantamkit import shiftwork\ncp,u,at=sys.argv[1],sys.argv[2],float(sys.argv[3])/1000\nwhile time.time()<at: pass\nprint(json.dumps(shiftwork.clock_out(cp,u,'done',{},{'unit':u,'outcome':'x'},{'tokens':1,'duration_ms':1})))`;
const nodeSnippet = `import {clockOut} from '${DIST}/shiftwork.js'; import {dumpJson,parseJson} from '${DIST}/pyjson.js'; const [cp,u,at]=process.argv.slice(1); while(Date.now()<Number(at)); process.stdout.write(dumpJson(clockOut(cp,u,'done',parseJson('{}'),parseJson(JSON.stringify({unit:u,outcome:'x'})),parseJson('{"tokens":1,"duration_ms":1}'))));`;
const child = (kind, cp, u, at) => new Promise((res) => {
  const c = kind === 'py' ? spawn(PY, ['-c', pySnippet, cp, u, at], { env: { ...process.env, PYTHONPATH: path.join(repo, 'runtime-py/src') } })
                          : spawn(process.execPath, ['--input-type=module', '-e', nodeSnippet, '--', cp, u, at], { env: process.env });
  let o = '', e = ''; c.stdout.on('data', (d) => (o += d)); c.stderr.on('data', (d) => (e += d)); c.on('close', (code) => res({ o, e, code }));
});
let okButLost = 0, errButCommitted = 0, both = 0, stray = new Set();
for (let t = 0; t < trials; t++) {
  const dir = path.join(W, `t${t}`); fs.mkdirSync(dir); const cp = path.join(dir, `cp${t}.json`);
  fs.writeFileSync(cp, JSON.stringify(checkpoint([unit('A'), unit('B')])));
  fs.writeFileSync(cp + '.log.jsonl', '{"event": "brief", "role": "implementer", "ts": "x", "unit": "B"}\n');
  const at = String(Date.now() + 1500);
  const out = await Promise.all([child(w1, cp, 'A', at), child(w2, cp, 'B', at)]);
  const doc = JSON.parse(fs.readFileSync(cp, 'utf8'));
  out.forEach((r, i) => { if (r.code !== 0) console.log('child failed:', r.e.slice(-400)); const ok = /"result": ?"ok"/.test(r.o); const disk = doc.plan.units[i].status === 'done'; if (ok && !disk) okButLost++; if (!ok && disk) errButCommitted++; });
  if (doc.plan.units.every((u) => u.status === 'done')) both++;
  for (const f of fs.readdirSync(dir)) if (f !== `cp${t}.json` && f !== `cp${t}.json.log.jsonl`) stray.add(f);
}
console.log(`${w1}-vs-${w2}: trials=${trials} okButLost=${okButLost}/${trials * 2} errorButCommitted=${errButCommitted} bothOnDisk=${both}/${trials} strayFiles=${[...stray].join(',') || 'none'}`);
```

"""Exact-match, exactly-once text substitution: sub.py <file> <old-file> <new-file>."""
import sys
from pathlib import Path
target, old_path, new_path = (Path(a) for a in sys.argv[1:4])
text = target.read_text(encoding="utf-8")
old = old_path.read_text(encoding="utf-8")
new = new_path.read_text(encoding="utf-8")
n = text.count(old)
if n != 1:
    sys.exit(f"{target}: expected exactly one match, found {n}")
target.write_text(text.replace(old, new, 1), encoding="utf-8")
print(f"patched {target}")

Closed (all four, both runtimes, each with a conformance case and a per-side literal):

- **#116** — `clock_out` holds `<checkpoint>.lock` (O_EXCL, one protocol in Python and Node) around
  the whole read-modify-write and writes through a per-writer `<real>.<pid>.<hex>.tmp` created
  exclusively; two writers on different units both land (0/20 lost, 30/30 trials across three
  pairings, §4), a suffix-less `checkpoint` never touches `checkpoint.tmp`, no stray file.
- **#137** — the rename lands on the resolved target; the link stays a link and `status` through
  either path sees the new cursor.
- **#163** — invalid UTF-8 answers `checkpoint unreadable: 'utf-8' codec can't decode byte 0xff in
  position 1: invalid start byte` from every tool, never raised.
- **#165** — a repeated unit id answers `duplicate node id <id>` (`work_plan`'s sentence) from every
  tool, nothing written, no log line.

Not closed: none of this unit's four.

Open questions for the orchestrator:

1. **#163's wording for invalid JSON.** The issue's (c) asks for `checkpoint unreadable: ...` on
   invalid JSON too. Invalid JSON already answered a structured `checkpoint is not parseable as
   JSON: ...` on both sides, pinned by existing tests and cases that are not this issue's
   contradiction (they already satisfy "never raised"), so under the never-weaken rule that
   sentence was left alone and only the UTF-8 arm took the `unreadable` head. If the issue's
   literal wording is wanted, that is a one-line rename on both sides plus the pins.
2. **`npm test` is red by one test that is not this unit's**: `test/contract.test.mjs:464`
   "an unresolvable construct raises rather than answering plausibly" — J65-3's `$ref` work,
   persists on a rerun (§5). The first agent's `--all` log (`<scratch>/j65-1/conf-all.log`)
   shows the matching `validate/ruling: $ref is not resolved — STALE RULING` from the same
   sibling. Nothing here touches it.
3. **The lock-refusal arm is a timing case.** `lock-held-by-another-writer` plants a fresh lock
   and the product waits `LOCK_WAIT_MS` = 5 s before refusing, on each side, so the session costs
   ~10 s of wall time per `--suite shiftwork` run. A test seam (`lockWaitMs` / monkeypatched
   `LOCK_WAIT_MS`) keeps the unit tests fast; the conformance harness has no such seam by design
   (it runs the product). Acceptable, but flagged in case the suite's wall time is budgeted.
4. **`docs/porting.md` and `docs/shiftwork.md`** carried only this unit's hunks at commit time
   (`git diff` checked immediately before `git add`); if a sibling adds a hunk between that check
   and its own commit, the orchestrator will see it as that sibling's.
