## What changed (runtime-ts/src/memory/factfile.ts)

- `scanNode` skips the spaces in front of a value, as PyYAML's `scan_to_next_token` does. It then dispatches on the indicator:
  - `|` and `>` go to the new `scanBlockScalar`. This is a line-by-line port of PyYAML's `scan_block_scalar`, its indicators, the ignored line, the indentation and the breaks, plus PyYAML's folding rule.
  - `[` goes to the new `scanFlowSequence`: one line of plain, single-quoted or double-quoted scalars, PyYAML's flow-context plain-scalar ends, and a trailing comma allowed.
  - `#` makes the value null, as a comment does in PyYAML.
  - The indicators `& * ! % @ \` { } ] ,`, a tab, and `-`, `?` or `:` followed by a blank all raise a named `FactParseError` (`REFUSED_INDICATORS`).
- A flow sequence that is nested, holds a pair, or runs over more than one line raises `FactParseError`.
- In plain scalars:
  - A tab now raises. PyYAML raises a ScannerError there, and Node used to answer.
  - `:` followed by a blank now raises wherever it appears. The old regex needed a blank before the colon too, so `a: b` was answered.
- `parseFrontmatter` skips blank lines and comment-only lines between entries. After a value it skips spaces and a trailing `#` comment, so `'x' #c` and `[a]#c` are read.
- Block-sequence items get the same trailing-comment skip.
- The docstrings were updated: the SCOPE ruling in factfile.ts and the `yaml` tag bullet in pyyaml.ts.

## Conformance (tools/conformance/suites/codec.mjs, ref op `reemit` in ref/codec_ref.py)

The new cases, under the `#120` names:

- **36 read-alike inputs.** Each one compares the parse side to side, and also the bytes a stamp writes back (Python `write_fact` against Node `formatFact`).
- **21 both-refuse inputs.** One side-to-side refusal-bit case, plus per-side literals: Python refuses all 21, and Node refuses all 21 with a named FactParseError.

## Issues

- **#120 closed.** Node's fact codec now reads block scalars and one-line flow sequences byte for byte as PyYAML does, including the bytes it stamps back. It refuses every other unimplemented indicator with a named FactParseError. A file it refuses is never stamped or rewritten (e2e: `disk unchanged: true`).

## Open questions

1. Where Python reads and Node refuses, the store refuses as a whole: anchors, `!!str`, flow mappings, nested or multi-line flow sequences, blank lines inside a block sequence. This is now ruled, with literals. Should a later job port the scanner, or is refusing by name the final answer?
2. A `description` that is a list (`[a, b]`, and before this, a block sequence) is rendered as `a,b` by Node and `['a', 'b']` by Python in the index line. This is the existing ruled "collection shapes" difference in store.mjs, not new here. It is now reachable through flow syntax too.
