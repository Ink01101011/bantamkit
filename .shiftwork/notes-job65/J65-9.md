## 2. What changed (both runtimes, same sentences)

- **#155** — save: after the strip, any C0/C1 control or U+2028/U+2029 is refused:
  `description must be one line; it holds the control character U+000A`. Read: a hand-edited
  description holding one is READ with each run of them as one space (not malformed: the
  issue allows "refuse or fold", and folding keeps the fact; `test_nativeexport`'s wrapped
  description exercises exactly this), and `lint` names it as a finding. Hook: UserPromptSubmit
  takes headers from `RecallOutcome.headers`, built from parsed fields (`Memory._header`),
  never from reply lines — closes the body-line vector too.
- **#156** — CHOICE: keep the normalisation (P1b's measured reason; tests pin `saved 'deploy-command'`
  for a new fact, and that reply already names the slug), but when the name had to be bent AND
  the slug is an existing fact, answer the duplicate nudge naming it and write nothing. Name cap
  `NAME_MAX_CHARS = 128` (room for `.md.<pid>.<8hex>.tmp` under 255): `invalid name: <n>
  characters; must be at most 128`.
- **#160** — store: `description`/`body`/`links[i]` with a lone surrogate →
  `<label> holds a lone surrogate (U+D800), which is not text and cannot be stored as UTF-8;
  nothing was saved`. Wire (any string argument of any served tool, nested paths `a[0].b`):
  `Error executing tool <name>: argument '<path>' holds a lone surrogate (U+XXXX), which is not
  text; nothing was done`. Node: `loneSurrogateArgument` first in `validateArguments`.
  Python: new `bantamkit/mcpstdio.py` — `serve_stdio(server)` = `run_stdio_async` with the stdin
  reader wrapped; a line with a `\uD8..`–`\uDF..` escape is re-read with stdlib `json` and, if it
  is a `tools/call` with an id for a served tool whose arguments hold one, answered via the
  write stream (bytes built as the SDK's own tool-error frame). Uses SDK private names
  (`_claim_fd`, `_open_stdin_diversion`, `_UnownedTextWrapper`, `_lowlevel_server`) — the SDK is
  capped `<2.1`; documented in the module docstring.
- **#185** — CHOICE: no URL on either side. `mcpserver.py` sets `PYDANTIC_ERRORS_INCLUDE_URL=0` at
  import (pydantic-core reads it lazily at the FIRST formatted error and caches it — measured:
  set after an error was formatted, the URL stays); `pyargs.ts` drops the line.
- **#186** — at `size >= budget` the condition reads `…, so it is full and every save is refused
  until it is compacted — archive or shorten facts with …`; the 90 % band keeps "close to".
  Same key `index-budget-low`, same `the memory index is ` head, so wire's ruled remedy cases hold.
- **#119 (recall half)** — store: `_facts(findings, skipped)`/`facts(findings, skipped)` split into a
  per-file `_read_fact`/`readFact`; `recall(..., skipped=)`, `lookup(..., skipped=)` and
  `readable_facts()`/`readableFacts()` (the declared tolerant listing). Every other reader keeps
  the strict read (the J65-6 `#159` store-level literal is unchanged and green). Component:
  each layer is read past bad files; `RecallOutcome.skipped` = `{layer, file, reason}`; the reply
  closes with `N fact file(s) could not be read and was/were skipped; every other fact was
  searched:` + `[layer] <store sentence>` lines. Hook: J65-8's private-seam workaround
  (`factPaths`/`_fact_paths` narrowing, `quarantineLayers`, re-ask) replaced by
  `store.readableFacts()` and `o.skipped`; its now-unused imports removed (lines J65-8 added).

After: `$E/probe-after.txt` — every row identical across runtimes; no `errors.pydantic.dev`
anywhere; Python answers both surrogate calls.
