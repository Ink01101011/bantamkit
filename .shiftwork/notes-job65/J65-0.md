### The 2 conformance failures are an ENVIRONMENT artefact, not a regression

Both are in `install`:

    ✖ install/install: the three refusal bits against a literal — the port
        python : {"git-origin":true,"http-origin":false,"unowned-file":true}
        node   : {"git-origin":true,"http-origin":false,"unowned-file":false}
    ✖ install/install: a running file no package.json owns is `checkout` on the reference and refused by the port — MALFORMED CASE

Cause: a stray manifest sits ABOVE the harness's temp root, so the port finds an "owner" for
the file the case built to be unowned:

    ls -la "$TMPDIR/package.json"
    # -rw-r--r--@ 1 kktest staff 3632 Oct 12 18:05 /var/folders/dy/.../T//package.json   ("name": "kk-debounce", 1.0.7)

Proof it is the cause (the suite passes once the temp root is not under that file):

    node tools/conformance/run.mjs --suite install                      # FAIL: 30 cases, ..., 2 failures  (reproduced twice)
    mkdir -p <scratch>/cleantmp && TMPDIR=<scratch>/cleantmp/ node tools/conformance/run.mjs --suite install
    # PASS: 30 cases, 0 byte-identical, 14 exact-string, 16 structural, 4 ruled-different, 0 failures

A TMPDIR *under* /var/folders/.../T (e.g. `mktemp -d`) does NOT help — it is still beneath the
stray file. I did not delete the file (not this unit's, not in the repo). EVERY later unit that
runs `--all` on this machine will see these 2 failures until the file is removed or they set
TMPDIR to a directory outside `/var/folders/dy/_97w57_x4rs15pqlpk55x4s00000gn/T`.

## 4. Premise-killers and collisions for later units

1. **`--all` shows 2 failures on this machine that are not the code's** (§1). Any unit quoting
   "0 failures" as its gate must either run with `TMPDIR` outside `/var/folders/…/T` or get the
   stray `$TMPDIR/package.json` removed first. Orchestrator decision.
2. **#164 is pinned by a conformance case on purpose**: `unit-id/cursor-disagrees-with-ready`
   expects `clock_in()` to brief the done cursor unit. The fix the issue asks for reddens a case
   whose comment says that is the point. Invariant: a question, not an edit.
3. **#162 is a documented design choice on Python**: `_briefed`'s docstring (shiftwork.py:200-207)
   picks the "retry reads briefed:false" edge deliberately, and `readonly-directory-after-the-log-line`
   pins the log-then-commit order. Same invariant applies.
4. **#138 is documented as deliberate on Python** (`_backup` docstring) while README promises
   the undo restores the original. The unit has to pick which contract wins and say so.
5. **#127's "Python behaves as expected" is false**: Python ignores the item schema too and
   refuses by accident (char-iterating a string `depends_on`; TypeError on a string priority).
   The unit must fix BOTH sides and the case must compare the refusal, not just Node's.
6. **#160 is shared**: Python raises a non-BantamError and leaves a `.md.tmp` behind; it is the
   same tmp #161 names, so the two should land in one unit or in sequence.
7. **#171 has no Python surface** (porting.md:327 row already exists); scope it Node-only.
8. **#141 on Python is two different wrongs** (000: same wrong sentence; 555: raw PermissionError),
   so the Python fix has two arms and the case needs both.
9. **#185 depends on what pip resolved**: pydantic is transitive and unpinned; the venv has 2.13.4
   today, which is why the conformance run is green on it.
