## 2. What changed (both runtimes, one shape)

`runtime-py/src/bantamkit/hostinstall.py` and `runtime-ts/src/hostinstall.ts`:

- **#118** `_read_config`/`readConfig`: the port now parses with `pyjson.parseJson` (the
  CPython decoder port) and the whole document is held as a tagged `PyValue` `Map` until
  `dumpJson` writes it — ints are `bigint`, `1.0` stays a float, key order is the file's. The
  reference already had all of that from `json.loads`. BOTH sides then walk the document
  (`_non_finite_in`/`nonFiniteIn`, depth-first, document order) and refuse the first non-finite
  float by location: `<path> has a number at mcpServers.other.huge that JSON cannot carry
  (Infinity); refusing to touch it` (exit 1, nothing written, no backup). The spelling in
  parentheses is what `json.dumps` would have written (`Infinity`, `-Infinity`, `NaN`); the
  location is keys joined by `.`, list indexes as `[n]`. The parse-error sentence on the port
  is now CPython's `<msg> (line L, column C)` byte for byte — see §5 on the retired ruling.
  NOT changed, on purpose: indent 2 and `ensure_ascii` escaping (both pinned by existing tests
  as the reason the two runtimes write identical bytes; the brief's property (a) names numbers,
  key order and unknown keys, not whitespace or escaping). Recorded as an open question in §7.
- **#129** `_without_ours`/`withoutOurs` + `_is_our_hook`/`isOurHook`: ownership is decided per
  inner command object; `_planned_hooks`/`plannedHooks` trims ours out of each block, drops a
  block only when it is left empty, and returns the count of OUR objects removed, which is now
  what the removal plan's first line counts (`7 hook entries` in the ordinary case, as before).
  `_is_ours`/`isOurs` (block-level) is kept as the fast "does this block hold one of ours" test
  and because `test_hostinstall_hooks.py` calls it directly.
- **#136** `_write_target`/`writeTarget`: `os.path.realpath` (non-strict) / `realpathSync` with a
  hand-followed fallback for a dangling link; the temp file is made beside the TARGET and
  replaced onto it; the mode is read from the target. The backup (`copy2`/`copyFileSync`, both
  follow the source link) is a regular file beside the link path the report names.
- **#138** `_backup_target`/`backupTarget`: the first free name — `<name>.backup-<date>`, then
  `.backup-<date>.1`, `.2`, … (`os.path.lexists`/`lstat`, so a dangling name counts as taken);
  `_backup`/`backup` and BOTH plan printers (`_hook_plan`, `_removal_plan` and their port
  twins) call it, so the plan names the file the write then makes. The `_backup` docstring that
  pinned the per-day overwrite on purpose is amended and says why (the issue outranks it;
  COMMON.md).

Build: `cd runtime-ts && npm run build` (clean). Lint: `.venv/bin/ruff check runtime-py tools`
→ `All checks passed!`.
